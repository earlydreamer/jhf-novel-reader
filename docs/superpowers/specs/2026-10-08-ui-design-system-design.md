# 화면 디자인 시스템과 Android UX 재설계

- 날짜: 2026-10-08
- 상태: 사용자 승인(대화 설계 3개 섹션), 구현 대기
- 선행 이슈: #92 (디자인 시스템과 앱 셸)
- 후속 이슈: #93 서재, #94 작품 제거, #95 목차, #96 리더, #97 설정, #98 회차 저장본 삭제, #99 원문 탐색 테마 (9절)

## 1. 배경과 목표

번역·저장·스트리밍·용어집·일괄 번역·제목 편집 기능이 main에 모였지만 화면은 브라우저 기본 버튼과 레거시 녹색 CSS(`src/ui/reader.css`)가 섞여 있다. 모든 행동이 같은 무게로 나열되고(독서 화면 버튼 9종), 목차 위에 용어집·일괄 번역 패널이 펼쳐져 있으며, 전역 배너가 모든 화면 상단에 쌓인다. 실기 인계에는 "문단 재번역 버튼을 찾지 못함"이 기록되어 있다.

목표는 다음과 같다.

- 색과 컴포넌트 질감은 kawaii-agent-desktop `DESIGN.md`의 Very Peri 기조를 따른다.
- 구조·크기·위계·동작·세부 규칙은 Android 플랫폼 관례(Material 3 Expressive, edge-to-edge, 시스템 뒤로 가기)를 따른다.
- 대비는 WCAG 2.2와 APCA(WCAG 3.0 초안의 Lc)를 함께 통과해야 한다.
- 화면당 주 행동 하나만 강조하고, 중요도가 낮은 기능은 메뉴·바텀시트·대화상자로 접는다.
- 모든 문구를 해요체로 통일한다(토스 앱인토스 UX 라이팅 가이드 기준).

## 2. 범위 밖

- 목록-상세 분할(태블릿·펼친 폴더블 전용 2단 배치). 폭 제한만 한다.
- 회차 전후 스와이프 이동(시스템 뒤로 가기 가장자리 제스처와 충돌).
- 본문 글꼴 선택(명조 번들). Pretendard 하나만 사용한다.
- 동적 색(Material You 배경화면 색). 브랜드 색을 고정한다.
- 번역 품질·제공자·저장 형식 변경. 단, 작품 제거(이슈 3)와 회차 저장본 삭제(이슈 7)는 저장소 삭제 API를 새로 만든다.

## 3. 접근 방식

의존성 없이 CSS 변수 토큰과 자체 React 컴포넌트를 만든다. `@material/web`은 유지보수 모드이고 M3 Expressive 컴포넌트가 없으며, 대형 UI 키트는 M2 계열이라 플랫폼 관례와 어긋난다. 앱의 화면은 5개라 소형 컴포넌트 집합으로 충분하다.

- 토큰 정본: `src/ui/theme/tokens.css`. 다른 CSS는 토큰만 참조하고 hex를 쓰지 않는다.
- 디자인 정본 문서: 저장소 루트 `DESIGN.md`. 이 스펙의 4~7절을 정리해 둔다.
- 컴포넌트: `src/ui/components/`. 화면: `src/ui/screens/`는 만들지 않고 기존 `src/ui/*Screen.tsx`를 각 이슈에서 재작성한다.

### 4.4 모양·크기·높이·모션

- 모양: `--shape-xs 4px`, `--shape-sm 8px`(칩·메뉴), `--shape-md 12px`(카드), `--shape-lg 16px`(FAB), `--shape-xl 28px`(시트 위 모서리·대화상자), `--shape-full 999px`(버튼·알약·플로팅 툴바).
- 크기: 터치 영역 최소 48px(`--touch-target`). 버튼 높이 `--button-m 56px`(화면 주 행동), `--button-s 40px`(나머지). 아이콘 버튼 40px(영역 48). 앱바 64px. 목록 행 56px(한 줄)·72px(두 줄). Extended FAB 56px. 플로팅 툴바 64px. 시트 손잡이 32×4px.
- 높이: 표면 깊이는 `surface-container-*` 톤으로 나눈다. 그림자는 FAB·플로팅 툴바·메뉴·대화상자에만 쓴다(`--elevation-2`, `--elevation-3`).
- 상태 레이어: 호버 8%, 포커스 10%, 눌림 10%, 드래그 16%(`currentColor` 기반 `::before`). 비활성은 내용 38%·면 12%의 `on-surface`.
- 포커스 링: `outline: 3px solid var(--primary); outline-offset: 2px`, `:focus-visible`에서만.
- 모션: `transform`·`opacity`만. 표준 이징 `cubic-bezier(0.2, 0, 0, 1)`. 짧은 전환 150ms, 시트·대화상자 열기 300ms·닫기 200ms. 스프링 느낌은 `linear()` 근사 이징 토큰 `--ease-spring`으로. `prefers-reduced-motion: reduce`에서 모든 전환을 0ms로.

## 6. 화면

### 6.1 내비게이션과 셸 (이슈 1)

- 계층은 `서재(home) → 목차(work) → 리더(translation·reader)`다. 설정은 서재 앱바에서 들어가고, 번역 화면의 `연결 설정하기`에서도 들어간다.
- Android 원칙대로 앱 안에서 앱바 `←`와 시스템 뒤로 가기는 같은 백스택(`back()`, 히스토리 기반)을 따른다. 그래서 리더에서 설정으로 들어갔다가 뒤로 가면 리더로 돌아온다.
- 백스택 규칙(컨트롤러 `navigate`):
  - 회차 단위 화면(`translation`·`reader`)에서 회차 단위 화면으로 가는 이동(번역 완료 후 리더, 이전·다음 화)은 스택에 쌓지 않고 현재 항목을 교체한다. 다음 화를 여러 번 넘겨도 뒤로 가기 한 번이면 그 회차에 들어오기 전 화면(보통 목차)으로 간다.
  - `showContents()`(목차): 바로 아래 항목이 같은 작품의 `work`면 새로 쌓지 않고 그 항목으로 돌아간다(`back()`과 같음). 이때 선택 회차는 현재 회차로 갱신한다.
  - `goHome()`(서재로 가기): 스택을 비우고 `home`으로 간다.
  - `canGoBack()`: 스택이 비어 있고 현재가 `home`이면 `false`.
- 시스템 뒤로 가기(`@capacitor/app` `backButton`): ① 열린 메뉴·시트·대화상자 닫기 → ② 리더 바가 보이면 숨기기 → ③ `canGoBack()`이면 `back()` → ④ 아니면 `App.exitApp()`. 오버레이와 리더 바는 셸의 작은 LIFO 레지스트리(`pushBackHandler`)에 등록한다.
- Manifest `application`에 `android:enableOnBackInvokedCallback="true"`를 둔다(앱 종료 시 predictive back 애니메이션).
- edge-to-edge: `viewport-fit=cover`와 `env(safe-area-inset-*)`. WebView가 인셋을 주지 않는 기기에서는 Capacitor 8의 시스템 바 기능 또는 네이티브 `WindowInsets`로 받은 값을 `--inset-top/bottom/left/right`에 넣는다. 구현 시 Black Shark 2(Android 10)와 Fold7(Android 16)에서 실제 값을 확인한다. 상태바 아이콘 밝기는 테마를 따른다.
- 화면 이동 시 새 화면 `h1`으로 포커스를 옮긴다.
- #92의 셸 앱바(하위 이슈가 화면별 앱바로 넘겨받기 전까지): 서재는 제목 `서재` + `설정` 아이콘 버튼, 나머지 화면은 `뒤로 가기` 아이콘 버튼 + 화면 이름(`목차`·`읽기`·`설정`) + `더보기` 메뉴(`서재로 가기`). 화면 본문이 이미 `h1`을 가지므로 셸 앱바 제목은 제목 요소가 아닌 텍스트로 둔다.
- 기존 `Application.tsx`의 상단 `뒤로/홈/설정` 버튼, 전역 배너 4종, 하단 `최근 번역 단계별 시간`은 셸에서 제거한다. 전역 배너는 서재의 알림 카드로(이슈 2), 단계별 시간은 설정의 정보로(이슈 6) 옮긴다. 이슈 1에서는 하위 이슈가 옮기기 전까지 셸의 알림 영역에 새 `Card` 컴포넌트로 임시 유지한다.
- 앱 테마: 설정 스키마 v2에 선택 필드 `theme?: 'system'|'light'|'dark'`(기본 `system`), `readingBackground?: 'theme'|'sepia'|'black'`(기본 `theme`), `lineHeight?: 1.6|1.8|2.0`(기본 1.8)를 추가한다. 키가 없는 기존 파일은 그대로 읽힌다. `html[data-theme]`로 적용하고 `system`이면 `prefers-color-scheme`을 따른다.

### 6.2 서재 (이슈 2)

- 앱바: `서재` · `URL로 열기` 아이콘(링크) · `설정` 아이콘.
- 알림 카드(있을 때만): 저장하지 못한 번역(오류 톤, `저장 화면으로 가기`), 저장된 일괄 번역 상태(`일괄 번역 보기`), 이전 데이터 일부 누락(정보, 펼쳐서 목록). 일시 알림(제목 번역 중, 일반 오류)은 스낵바.
- 이어서 읽기 카드(`primary-container`): `이어서 읽기` / 작품명 / `12화 · 회차 제목`. 카드 전체가 버튼이고 리더를 연다.
- 작품 목록: `library/index.workIds` 전체(열어 본 작품 자동 등록). 두 줄 행: 번역 제목 / `N화 저장 · 오늘 읽음` 또는 `아직 번역하지 않았어요`. 뒤 `⋮`: `원문 사이트에서 보기`, `서재에서 제거하기`(이슈 3 전에는 숨김). 정렬은 최근 읽음 시각, 없으면 등록 순서의 역순.
- `작품 찾기` Extended FAB(화면의 유일한 강조 행동). 원문 연결을 쓸 수 없으면 누를 때 스낵바로 이유를 알린다.
- 빈 상태: 제목 `읽고 싶은 작품을 찾아보세요`, 본문 `나로우에서 작품을 고르면 서재에 담겨요.`
- `URL로 열기` 대화상자: 입력칸 하나, 버튼 `닫기` / `열기`.
- 컨트롤러는 `LibraryStore`에 이미 있는 `workIds`와 `readWork`로 목록을 만든다. 새 저장소 API는 필요 없다.

### 6.3 작품 제거 (이슈 3)

- `LibraryStore.removeWork(workId)`: 작품 목차 페이지, 그 작품의 모든 버전·읽기 위치·`recent` 항목, 제목 저널(`titles/<workId>`), 용어집을 삭제하고 인덱스에서 뺀다. 저널 원자성 규칙을 따른다(인덱스 갱신 후 파일 삭제, 중간 실패 시 인덱스 기준으로 고아 파일만 남고 읽기는 정상).
- 일괄 번역이 진행 중이거나 저장 대기 번역이 그 작품이면 제거하지 않고 이유를 대화상자에 적는다.
- 확인 대화상자: 제목 `{작품}을 서재에서 제거할까요?`, 본문 `이 기기에 저장한 번역 N화, 읽던 위치, 번역한 제목, 용어집이 함께 삭제돼요. 삭제한 내용은 되돌릴 수 없어요.`, 버튼 `닫기` / `제거하기`(danger).
- 진입점: 서재 행 `⋮`, 목차 앱바 `⋮`. 제거 후 서재로 이동하고 스낵바 `서재에서 제거했어요`.

### 6.4 목차 (이슈 4)

- 앱바: `←` · 작품 제목(말줄임) · `⋮`: `용어집 편집하기`, `미리 번역하기`, `목차 제목 번역하기`, `원문 사이트에서 보기`, `서재에서 제거하기`.
- 헤더: 번역 제목(headline-small), 원제(`lang="ja"`, 보조색), 메타(`총 120화 · 12화 저장` 또는 `45화까지 확인했어요`), M 채움 버튼 하나(`12화부터 이어서 읽기` / `1화부터 읽기`).
- 일괄 번역 진행 중이면 헤더 아래 고정 카드: `미리 번역하는 중 · 3/10화` + `중단`. 누르면 미리 번역 대화상자.
- 회차 행: 화수 · 제목(번역 또는 원제) · 보조 줄(`저장됨`, `읽는 중`, `제목 번역 전` 조합) · 뒤 `⋮`. 롱프레스(`contextmenu`)와 `⋮`가 같은 바텀시트를 연다: `제목 번역하기`/`제목 다시 번역하기`, `제목 직접 고치기`, `원문 사이트에서 보기`(이슈 7 후 `이 화 저장본 삭제하기`). 읽는 중 회차는 `primary-container` 강조, 화면을 열면 그 행으로 스크롤.
- 행 탭: 저장본이 있으면 리더, 없으면 리더에서 번역 시작(자동 시작 옵션을 따른다).
- `용어집 편집하기`, `미리 번역하기`: 전체 화면 대화상자. 기존 `GuidancePanel`·`BatchPanel`·`CandidateReview`의 동작은 유지하고 표현만 새 컴포넌트로 바꾼다. 미리 번역하기는 `범위 고르기 → 후보 확인 → 진행` 단계 표시.
- 제목 직접 고치기: 기본 대화상자(원제 표시 + 입력칸, `닫기` / `저장하기`).
- 목록 끝: S 토널 `다음 목차 불러오기`.

### 6.5 리더 (이슈 5)

`TranslationScreen`·`StreamingReader`·`ReaderScreen`을 하나의 리더 화면으로 합친다. 라우트(`translation`, `reader`)와 컨트롤러 계약은 유지하고 표현만 통합한다.

- 몰입 상태(기본): 본문만 보인다. 회차 화수와 제목은 본문 맨 위에 있어 함께 스크롤된다. 본문 가운데(가로 60%) 탭으로 바 토글, 아래로 스크롤하면 숨고 위로 스크롤하면 나타난다. 숨은 바는 `inert`.
- 앱바: `←`(목차로) · 회차 제목 · 원문/번역 전환 아이콘 버튼(`aria-pressed`) · `⋮`: `번역 확인 결과 보기`(바텀시트, 기존 품질 표시 내용), `문단 골라 다시 번역하기`(선택 모드), `실패한 문단 다시 번역하기`(있을 때), `제목 다시 번역하기`, `제목 직접 고치기`, `원문 사이트에서 보기`, `번역 정보`(모델·경과 시간 바텀시트), `서재로 가기`.
- 플로팅 툴바: `이전 화` · `목차` · `보기 설정(Aa)` · `다음 화`.
- 보기 설정 바텀시트: 독서 배경(세그먼트 3개), 글자 크기(`−` 값 `+`, 2px 단위), 줄 간격(세그먼트 3개).
- 번역 상태(바가 숨어 있어도 보인다):
  - 읽으며 번역 중: 화면 맨 위 `LinearProgress`, 하단 `StatusPill` `번역하는 중 · 3/8묶음` + `중단`. 아직 도착하지 않은 자리에 `다음 문단을 번역하고 있어요…`.
  - 기존 묶음 방식: 본문 자리에 단계(`원문 준비 → 모델 응답 대기 → 결과 확인 → 저장`)와 경과 시간.
  - 번역 전(자동 시작 꺼짐): 제목 아래 M 채움 `이 화 번역하기`. 연결 전이면 대신 카드 `번역 서버를 연결하면 바로 읽을 수 있어요` + `연결 설정하기`.
  - 실패·결과 불명: 본문이 멈춘 자리에 오류 카드. 원인 한 문장 + 행동 하나(`저장 다시 하기` / `중복 가능성을 확인하고 다시 번역하기` / `연결 설정하기`). 자동 재전송하지 않는다는 기존 계약을 유지한다.
  - 실패 문단: 본문 안 왼쪽 3px `--error` 막대 + 원문 + `번역하지 못해 원문으로 남겼어요 · 길게 눌러 다시 번역해요`.
  - 원문 변경: 본문 위 카드 `원문이 바뀌었어요` + `새 원문으로 번역하기`.
  - 회차 끝: 카드 `N화를 다 읽었어요` + M 채움 `N+1화 읽기`(마지막 화면 버튼 없이 `마지막 화까지 읽었어요`).
- 문단 롱프레스: 바텀시트 `이 문단 다시 번역하기`, `이 문단 원문 보기`. 본문 텍스트 선택은 막힌다(의식한 트레이드오프, 복사 기능은 범위 밖).
- 첫 포커스 요소는 포커스 시에만 보이는 `읽기 메뉴 열기` 버튼(바 표시).
- 독서 위치 저장·복원, 원문 전환 시 위치 유지, 미리보기 위치 계약은 기존 테스트를 그대로 통과해야 한다.

### 6.6 설정 (이슈 6)

앱바 `←` `설정`. M3 목록형 설정, 섹션 머리말.

1. 번역 서버: 연결 상태 줄(상태 문구), 제공자(라디오 대화상자, Gemini 선택 시 비용·전송 안내 대화상자 먼저), API 주소(입력), 인증값(입력, 비밀번호 형태·저장 후 비움), `연결 확인하기`(S 토널), 모델(라디오 대화상자, 생성 불가 모델은 비활성 행).
2. 번역 방식: 로컬 번역 방식(`읽으며 번역`/`기존 묶음 방식` 라디오 대화상자), `저장본이 없으면 자동으로 번역 시작`(스위치), `실패한 문단 자동으로 다시 번역`(스위치).
3. 화면: 테마(`시스템 설정 따르기`/`라이트`/`다크` 라디오 대화상자).
4. 정보: 버전, 오픈소스 라이선스, 최근 번역 시간(기존 단계별 시간).

### 6.7 회차 저장본 삭제 (이슈 7, 후순위)

`LibraryStore.removeChapterVersions(chapterId)`. 목차 회차 바텀시트 `이 화 저장본 삭제하기` → 확인 대화상자 → 목차 상태 갱신. 읽는 중 버전이면 `recent`에서도 뺀다.

### 6.8 원문 탐색 테마 (이슈 8, 후순위)

네이티브 `SourceBrowserActivity` 툴바를 토큰 값(라이트·다크)과 맞추고 시스템 다크 모드를 따른다. 네이티브 계측 테스트의 문구(`취소`, `외부 링크`)를 해요체 규칙에 맞추면 함께 고친다.

## 7. UX 라이팅

토스 [앱인토스 UI/UX 가이드의 UX 라이팅](https://developers-apps-in-toss.toss.im/design/consumer-ux-guide.md)을 기준으로 한다.

- 모든 문구는 해요체. `되어요` 대신 `돼요`.
- 능동형(`저장됐어요` → `저장했어요`). 수동형은 만료·사용자 영향·안심 안내에만.
- 긍정형(`~할 수 없어요` → `~하면 ~할 수 있어요`). 정말 불가능한 일만 부정형.
- 과도한 경어 금지(`~시겠어요`, `~께`, `계시다`).
- 명사 나열 대신 동사로 풀어 쓴다(`제목 미번역` → `제목 번역 전`, `저장 12화` → `12화 저장`).
- 대화상자 왼쪽 버튼은 `닫기`. 오른쪽 버튼은 결과를 예측할 수 있는 동사(`제거하기`, `저장하기`, `열기`).
- 메뉴 항목은 `~하기`. 칩·상태 라벨은 짧은 형태 허용(`저장됨`, `읽는 중`).
- 오류는 원인과 다음 행동을 한 문장으로 한 번만 말한다. 같은 오류를 여러 곳에 반복하지 않는다.
- 내부 용어(바이트, 토큰, 요청 ID)를 기본 표시에 쓰지 않는다. 필요하면 `번역 정보`·설정 정보에 둔다.
