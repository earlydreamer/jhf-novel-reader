# Narou Reader 기능 리뉴얼 기획

기획 검토본 1.0 · 기준 소스 acb473b · earlydreamer/narou-reader

## 1 만들려는 경험

앱 안에서 나로우 작품을 찾고, 목차에서 고른 한 화를 통째로 번역한 뒤, 완성된 번역문을 전용 리더에서 읽는다. 다음 화로 이동하거나 앱을 다시 열어도 읽던 흐름이 이어져야 한다. 이번 리뉴얼의 완료 기준은 이 흐름이 실제 휴대폰과 로컬 모델에서 끝까지 동작하는 것이다.

이 문서는 기능과 동작 범위를 정한다. 화면의 시각적 완성도는 이후에 다루되, 화면 분리와 뒤로 가기, 읽기 위치, 글자 크기처럼 사용에 필요한 요소는 이번 범위에 포함한다. 문서 승인 뒤 별도의 구현 계획을 검토하며, 그 계획까지 승인한 후 재구현한다.

### 고정 요구사항

- 앱 내 탐색, 작품 제목과 목차, 원하는 회차 선택, 완료 후 읽기, 이전·다음 화, 이어 읽기를 연결한다.
- 선택한 한 화는 한 번의 시작 동작으로 처리한다. 로컬 모델은 실제 서버 컨텍스트에 맞춰 문단·문장 경계의 일반 텍스트 구간을 순차 요청하고, 모든 구간을 저장한 뒤 한 개의 완성본으로 읽는다. 진행 구간 수를 표시하며 자동 재전송이나 출력 보정용 추가 호출은 하지 않는다. 2026-10-07 사용자 승인과 #74가 기존 회차당 단일 요청 조건을 변경한다.
- PC·리눅스 서버의 LM Studio·Ollama·llama.cpp OpenAI 호환 API에 휴대폰이 Tailnet 주소나 IP로 직접 연결한다. 사용자가 지정한 리눅스 모델 서버를 검증에 사용하며 앱 전용 중계 서버를 추가하지 않는다.
- 서버의 실제 모델 목록에서 고른다. 앱 사용자가 컨텍스트 길이나 출력 토큰 예산을 계산해 입력하지 않는다.
- HyMT2 계열을 우선 검증한다. 모든 모델에 JSON 출력이나 구조화 출력 지원을 요구하지 않는다.
- 저장된 번역은 현재 연결·모델 설정과 독립적으로 읽을 수 있어야 한다. 로컬 연결 실패 시 Gemini 등 다른 제공자로 자동 전환하지 않는다.

### 이번 문서의 제안 결정

탐색은 격리된 원문 웹 화면에서 하고, 인식한 작품의 목차와 번역문은 앱이 관리하는 혼합형 흐름을 권장한다. 웹 탐색 화면 전체를 번역하는 방식도 가능한 대안이지만 첫 리뉴얼의 필수 기능에서는 제외한다. 선택 이유는 작품을 찾는 기존 사이트의 기능을 활용하면서, 읽기와 저장을 사이트 화면 변화로부터 분리할 수 있기 때문이다.

### 현재 상태와 바꾸는 이유

기준 소스는 acb473b이다. 작품·목차 파서는 있으나 작품을 열면 첫 화로 넘어가는 흐름, 리더 위에 붙은 설정, 수동 모델·예산 입력, 청크 중심 처리를 다시 정리해야 한다. 기존 네이티브 검증 결과만으로 전체 독서 경험의 완료를 선언할 수 없다.

실기기에서는 HyMT2 7B가 HTTP 200과 정상 종료 신호를 반환했지만 JSON 문법 검사에 막혀 완성된 본문을 읽지 못했다. 이 결과로 번역 속도가 느리다고 판단할 수 없다. 정상 번역을 읽는 경로를 먼저 성립시키고 그다음 시간을 측정한다. [1][2]

## 2 탐색에서 회차 선택까지

### 시작 화면과 화면 역할

앱을 열면 최근 읽은 작품과 이어 읽기, 작품 탐색 진입점이 보인다. 읽던 작품이 없으면 탐색으로 시작한다. 연결 설정은 별도 화면으로 둔다. 설정이 없어도 탐색·목차와 이미 저장한 번역은 사용할 수 있고, 새 번역을 시작할 때만 연결 설정을 요청한다.

- 탐색 화면은 나로우 사이트가 제공하는 검색·랭킹·분류와 일반 링크 이동을 이용한다. 앱 전용 검색 서버를 만들지 않는다. 뒤로 가기는 탐색 이력 안에서 동작한다.
- 작품 화면은 제목, 원문 링크, 목차, 마지막으로 읽은 회차와 저장 상태를 보여 준다.
- 리더 화면은 한 회차의 완료된 번역문과 독서 이동만 맡는다. 설정과 긴 작업 로그를 본문 위에 계속 노출하지 않는다.

### 작품을 앱으로 가져오기

탐색 중 지원되는 작품 또는 회차 주소를 만나면 앱의 신뢰된 영역에 ‘이 작품 열기’를 제공한다. 누르면 주소를 정규화하고 작품을 인식한 뒤 제목과 목차를 연다. 작품을 열었다는 이유로 첫 화를 자동 번역하지 않는다.

URL 붙여넣기도 같은 작품 화면으로 들어가는 보조 경로로 유지한다. 회차 URL로 들어오면 해당 회차를 목차에서 선택해 보여 주되, 번역 전에는 작품명과 회차명을 확인할 수 있어야 한다. 원문 링크는 언제든 다시 열 수 있다.

### 목차의 기본 동작

- 회차 제목과 순서를 원문 기준으로 보여 준다. 번역 저장 여부와 마지막 읽은 회차를 구분한다.
- 목차가 여러 페이지이면 처음 받은 목록을 전체 목록으로 오인하지 않는다. 현재 범위와 다음 목차 페이지를 표시하고 사용자 동작으로 더 읽어 온다.
- 모든 회차의 본문을 미리 가져오지 않는다. 선택한 회차의 본문만 가져온다.
- 목차 새로고침은 명시적으로 실행하며 기존 번역과 읽기 위치를 지우지 않는다. 회차 식별은 목록의 화면 위치에 의존하지 않는다.
- 끝 회차에서는 다음 화가 없음을 표시한다. 링크가 삭제되거나 구성이 바뀌면 그 회차의 오류를 알리고 목차로 돌아갈 수 있게 한다.

### 회차를 누른 뒤

저장된 번역이 있으면 바로 연다. 없다면 회차 제목과 사용할 제공자·모델을 확인할 수 있는 번역 대기 화면을 보여 준다. ‘이 화 번역’을 누르면 원문 준비, 번역 요청, 결과 확인, 저장을 거쳐 리더로 이동한다. 진행 중에는 현재 단계와 경과 시간을 보여 주며 근거 없는 완료 비율은 표시하지 않는다.

리더의 다음 화를 눌렀을 때도 같은 규칙을 적용한다. 저장된 다음 화는 바로 읽고, 번역이 없으면 해당 화의 번역 대기 화면으로 간다. 이전 화로 돌아갈 때는 그 화의 읽던 위치를 복원한다.

## 3 연결과 한 화 번역 계약

### 처음 연결하기

제공자를 고르고 엔드포인트와 필요한 경우에만 인증값을 입력한다. ‘연결 확인’은 서버 접근과 인증을 확인하고 실제 모델 목록을 가져온다. 사용자는 목록에서 모델을 선택한다. 모델명을 임의로 추측하거나 기본값으로 숨겨 넣지 않는다.

연결됨, 인증 실패, 모델 목록 조회 실패, 사용 가능한 모델 없음은 구분한다. 목록을 읽을 수 있다는 사실과 번역 호환성이 검증됐다는 사실도 구분한다. 서버에서 모델이 바뀌면 목록 새로고침으로 반영하고, 선택한 모델이 사라졌을 때는 다른 모델로 자동 대체하지 않는다.

로컬 경로는 LM Studio·Ollama·llama.cpp의 OpenAI 호환 API이다. Gemini는 사용자가 직접 고르는 별도 선택지로 유지한다. 선택 전에 Google로 본문을 보내는 점과 비용 발생 가능성을 알린다. 제공자를 바꿔도 기존 번역은 남으며, 새 번역의 대상만 달라진다.

### 요청 단위와 한도

번역 버튼 한 번은 해당 회차의 원문 전체를 정확히 한 번씩 포함하는 번역 작업에 대응한다. 로컬 모델의 실제 요청은 구간별로 순차 전송하고 수와 적용 예산을 기록한다. 모델 목록 조회와 원문 가져오기는 생성 요청과 구분한다. 동시에 활성화되는 번역 요청은 하나로 제한하며, 스트리밍과 부분 번역 표시는 하지 않는다.

앱에 컨텍스트·출력 예산 입력란을 두지 않는다. 모델 자체의 입력·출력 용량, 서버의 현재 설정, 제공자 API 제한을 구분해서 다룬다. 서버 설정을 늘려도 모델의 최대 용량을 넘을 수는 없다. API상 필수 제한값은 어댑터가 지원 범위 안에서 처리하며, 임의의 작은 값으로 본문을 자르지 않는다. 모든 서버의 용량을 자동으로 알 수 있다고 가정하지 않고, 신뢰할 수 없는 추정만으로 정상 회차를 차단하지 않는다.

입력 초과, 출력 잘림, 길이 제한이 확인되면 완료로 저장하지 않고 기존 읽기 상태를 유지한다. 실제 용량 안에서 서버 설정을 조정하거나 적합한 모델을 선택할 수 있도록 원인을 알린다. 긴 회차를 몰래 나누거나 나머지를 추가 요청하지 않는다.

### 모델에 맞는 번역문 받기

HyMT2의 기본 계약은 한국어 번역문을 일반 텍스트로 받는 것이다. 원문과 번역 지시를 분리하고 순서, 문단 구분, 대사, 빈 줄의 의미를 유지하도록 요청한다. JSON, 문단 ID 출력, 특정 스키마 기능을 전제하지 않는다.

구조화 출력은 해당 제공자·모델에서 실제로 검증한 별도 계약에만 적용할 수 있다. 모든 모델에 동일한 strict JSON을 강제하는 기존 방향은 이 요구와 함께 다시 검토한다. 계약이 맞지 않으면 한 번의 실패로 알리고 다른 출력 방식으로 숨은 재호출을 하지 않는다.

원문은 문단과 루비 정보를 보존한다. 모델 입력에는 루비의 기반 문자와 읽기 정보를 중복·누락 없이 전달하도록 정규화한다. 번역문에는 근거 없는 루비를 새로 만들지 않는다. 정규화와 전달 방식은 승인 후 구현 계획에서 구체화하고 합성 예제 및 실제 우선 모델로 확인한다.

## 4 완료된 번역과 읽기 데이터

### 완료 판정과 그 한계

HTTP 성공만으로 완료 처리하지 않는다. 빈 응답, 제공자가 보고한 잘림·차단·오류, 명백한 오류 메시지, 저장 실패를 구분한다. 일반 텍스트 계약에서는 JSON 파싱이나 원문 문단 ID의 강제 일치가 성공 조건이 아니다.

문단 유지와 내용 충실성은 별도의 품질 기준이다. 번역 모델이 문단을 합치거나 내용을 누락했는지 자동 검사만으로 완전히 보장할 수는 없다. 숫자·반복 문장·대사·루비가 포함된 검증용 회차와 허가된 실제 회차로 순서와 누락을 확인한다. 단순히 문단 수가 다르다는 이유만으로 정상 번역을 거절하지 않으며, 자동 복구 호출로 품질을 보정하지 않는다.

원문 구조와 번역문 구조를 각각 저장한다. 원문 문단과 번역 문단이 언제나 일대일로 대응한다고 가정하지 않는다. 초기 원문 확인은 회차 단위로 제공하고, 정밀한 문단 대조 기능은 이번 완료 조건에 넣지 않는다.

### 읽기 화면

번역과 저장이 완료되면 회차 제목과 본문을 전용 리더에서 연다. 글자 크기와 기본 행간·여백을 읽기 좋은 수준으로 제공한다. 원문 확인, 목차, 이전·다음 화, 뒤로 가기가 본문을 가리지 않아야 한다. 장식, 테마 확장, 애니메이션 고도화는 후속 작업으로 둔다.

읽기 위치는 작품·회차와 저장된 번역 버전을 기준으로 보존한다. 앱 재실행 시 마지막 회차와 위치를 복원하고, 다른 화를 오갔다가 돌아와도 각 화의 위치를 유지한다. 저장된 번역을 읽는 데 모델 접속이나 새 생성 요청은 필요하지 않다.

### 저장할 정보와 재사용 규칙

- 작품과 회차의 식별자, 원문 정규 주소, 제목, 회차 순서, 확인한 목차 범위를 저장한다.
- 실제 가져온 원문, 원문 해시, 가져온 시각, 원문 문단·루비 구조를 보존한다.
- 번역문과 생성 시각, 제공자·모델, 비밀값을 제외한 연결 식별 정보, 번역 계약·프롬프트 버전, 언어 방향을 함께 저장한다.
- 연결 설정 변경은 기존 번역의 삭제나 읽기 차단 사유가 아니다. 새 번역을 만들 때는 바뀐 설정을 사용한다.
- 원문이 바뀌어도 기존 번역을 조용히 덮어쓰지 않는다. 원문 변경을 알리고 명시적으로 재번역한 결과를 별도 버전으로 저장한다. 새 결과가 정상 저장되기 전에는 기존 결과를 유지한다.

### 중단과 저장 실패

번역 도중 앱을 닫았다고 원격 생성이 취소됐다고 보장하지 않는다. 다음 실행에서 미완료 상태를 알리고 사용자 재시도를 기다린다. 자동 재개·자동 중복 전송은 하지 않는다. 저장 실패는 번역 실패와 구분하며, 결과가 메모리에 남아 있으면 모델 호출 없이 저장만 다시 시도할 수 있게 한다.

## 5 탐색 보안과 실패 처리

### 원문 웹 화면과 앱 기능의 경계

원문 사이트의 HTML과 스크립트는 신뢰하지 않는다. 탐색 화면은 인증값을 가진 앱 네이티브 브리지와 격리한다. 웹페이지에서 모델 서버 호출, 비밀값 읽기, 임의 파일 접근을 요청할 수 없어야 한다. 인증값을 DOM, 페이지 스크립트, 원문 요청 헤더, 진단 로그에 넣지 않는다.

앱으로 넘어오는 동작은 지원 소스에서 인식한 작품·회차 열기로 한정한다. 앱이 출처, URL 형식과 정규 식별자를 다시 검사하며, 웹페이지가 넘긴 임의 주소를 모델 요청 대상으로 쓰지 않는다. 탐색의 일반 링크 이동과 앱의 원문 추출 권한을 분리한다. 리다이렉트와 다른 도메인으로의 이동에서도 비밀값이 따라가지 않아야 한다.

### 사용자에게 보여 줄 오류

| 상황 | 화면에서 알릴 내용과 다음 동작 |
| --- | --- |
| 서버 연결 또는 인증 실패 | 연결·인증 중 무엇이 실패했는지 보여 주고 설정 확인으로 연결한다. 저장된 번역은 계속 읽을 수 있다. |
| 목차 또는 본문 추출 실패 | 문제가 생긴 작품·회차를 알려 주고 원문 열기, 목차 복귀, 사용자가 누르는 재시도를 제공한다. |
| 입력 초과 또는 출력 잘림 | 한 화가 현재 한도에서 완료되지 않았음을 알린다. 서버 설정·모델을 바꾼 뒤 다시 시도한다. |
| 요청 결과 불명 또는 중단 | 이미 서버가 처리했을 수 있음을 설명한다. 특히 유료 제공자는 중복 비용 가능성을 알리고 명시적으로 재시도한다. |
| 출력 또는 저장 실패 | 번역 결과 문제와 기기 저장 문제를 분리한다. 기존 완료 번역을 보호하고 저장 재시도에 새 모델 호출을 붙이지 않는다. |

동일 버튼의 연속 탭, 화면 이동, 설정 변경으로 중복 번역이 발생하지 않아야 한다. 늦게 도착한 응답을 다른 작품·회차에 붙이지 않는다. 전송 후 취소는 기기에서 기다리기를 그만두는 것과 서버 처리를 멈추는 것이 다름을 반영한다.

### 소스 이용 범위와 배포 위험

파서 코드의 라이선스와 소설 원문의 접근·번역 권한은 별개다. 현재 문서는 원문 이용 허가나 사이트 약관 문제가 해결됐다고 선언하지 않는다. 공개 배포 전에 최신 이용 조건, 자동 접근 제한, 원문·번역 저장 및 이용 범위를 확인한다. [1]

사용자가 고른 작품과 회차만 처리하고 전체 작품의 자동 수집, 접근 제한 우회, 로그인 우회, 번역문 공개 재배포는 이번 범위에 넣지 않는다. 접근이 제한되면 해당 요청을 멈추고 이유와 대안을 알린다. 이 위험을 이유로 모든 탐색을 제거하거나 불필요하게 광범위한 기능 차단을 기본값으로 두지는 않는다.

## 6 사용 흐름으로 확인하는 완료 기준

합성 데이터 테스트, APK 검사, 실제 기기 검증을 구분해 기록한다. 테스트 개수가 많다는 이유로 한 화를 끝까지 읽지 못하는 상태를 완료로 처리하지 않는다. 아래 흐름을 우선 대상 휴대폰과 실제 LM Studio·Ollama 연결 경로에서 확인한다. HyMT2 7B는 첫 번째 호환성 검증 대상이다.

| 확인할 흐름 | 통과 조건 |
| --- | --- |
| 앱 안에서 작품 발견 | 사이트가 실제 제공하는 검색·랭킹·분류 중 하나로 작품을 찾아 제목·목차를 열고 원하는 회차를 고른다. URL 입력만으로 통과할 수 없다. |
| 보조 URL 진입 | URL 붙여넣기로 같은 작품·목차 흐름에 들어간다. 회차 URL이면 해당 회차를 표시하고 첫 화를 자동 번역하지 않는다. |
| 여러 페이지의 목차 | 다음 목차 페이지의 회차를 선택해도 작품과 순서가 맞다. 아직 읽지 않은 목록을 전체라고 표시하지 않는다. |
| 첫 연결 | 엔드포인트·선택적 인증으로 연결을 확인하고 실제 목록에서 모델을 고른다. 수동 예산 입력이 없다. |
| 한 화 번역 | 정규화된 원문 전체가 순서대로 정확히 한 번씩 요청에 포함된다. 구간별 요청 수와 실제 한도를 확인하고, 모든 구간의 저장 전에는 부분 본문을 공개하지 않는다. 자동 복구 호출과 다른 제공자 전환이 없다. |
| 완료 후 읽기 | 정상 한국어 번역이 저장된 뒤 리더에 나타난다. JSON 형식을 지원하지 않는 모델도 검증된 텍스트 계약으로 읽을 수 있다. |
| 다음 화와 돌아가기 | 다음 화의 저장 여부에 맞게 읽기 또는 번역 대기로 이동한다. 이전 화와 목차로 돌아가도 회차와 위치가 맞다. |
| 종료와 재실행 | 완료 번역과 위치가 복원된다. 미완료 요청은 자동 재전송하지 않는다. |
| 모델 변경과 오프라인 | 현재 모델을 바꾸거나 연결을 끊어도 기존 완료 번역을 읽는다. 새 번역만 새 설정을 사용한다. |
| 실패와 안전 경계 | 긴 회차, 잘림, 인증 실패, 저장 실패가 구분된다. 웹 콘텐츠가 비밀값이나 임의 네이티브 호출에 접근하지 못한다. |

### 속도는 정상 경로가 열린 뒤 측정

원문 준비, 모델 응답 대기, 결과 처리·저장, 리더 표시까지의 시간을 나눠 측정한다. 작품 본문, 인증값, 사설 엔드포인트를 진단 로그에 남기지 않는다. 모델·기기·서버 설정과 회차 길이 범위를 함께 기록해야 비교가 가능하다.

대표 회차의 실제 요청·저장·독서 시간과 의미 보존을 측정한 뒤 성능 개선의 우선순위를 정한다. #75에 따라 범위 지정·전체 회차 일괄 번역을 포함한다. 사용자가 전체 목차의 범위와 기존 저장본 수를 확인하고 시작하면 포그라운드에서 회차를 순차 처리하며, 완성본만 읽는다. 백그라운드·재시작 시 자동 요청과 다음 화 자동 미리 번역은 하지 않는다.

## 7 레거시 격리와 진행 순서

### 리뉴얼과 기존 작업의 관계

기획이 정리되면 리뉴얼 흐름으로 재구현하고 기존 구현은 별도 보존 경로에 격리한다. 기존 코드·기록은 추적할 수 있게 유지하되, 새 사용자 흐름과 레거시 동작이 혼재하지 않게 한다. 현재 로컬 작업 트리의 커밋되지 않은 변경은 건드리지 않는다.

레거시 구현 이슈는 새 이슈와 대체 사유를 남기고 닫는다. #10의 기존 계획과 #8의 실기기 검증은 새 계획·수용 기준으로 옮긴다. #20의 문맥 ID 혼동과 #22의 JSON 실패는 새 번역 계약의 회귀 사례로 이어받은 뒤 대체 종료한다. 실패가 해결됐다고 표시하지 않는다. #23은 APK 검사 도구를 유지한다면 새 담당 이슈를 정한 뒤 정리한다. 이미 닫힌 이슈의 기록은 유지한다. #21의 용어집·말투는 후속 요구로 남기고 기존 청크·JSON 전제는 재검토한다. [2][3][4]

파서, 네이티브 전송의 분리, 비밀값 보호, 검증된 저장 기능은 새 요구에 맞는 부분만 재사용한다. 청크·작업 중심의 흐름과 화면 이동은 새 독서 경험을 기준으로 바꾼다. 기존 저장 형식이 다르면 완료 번역과 위치를 보존하는 이전 경로를 먼저 검증한다. 호환되지 않는 미완료 작업을 자동 재개하지 않는다.

### 기능 단위의 구현 순서 제안

1. 작품 발견, 목차에서 한 회차 선택, 모델 선택, 전체 번역 작업, 저장, 독서를 연결하고 실제 기기로 확인한다. 후속 구현은 사용자의 계속 진행 승인에 따라 수행하며, 번역 의미 보존이 실패한 상태를 병합 가능이나 품질 완료로 보고하지 않는다.
2. 독서를 이어 간다. 여러 페이지 목차, 이전·다음 화, 위치 저장, 종료·재실행, 오프라인 읽기, 모델 변경 후 기존 번역 열기를 확인한다.
3. 실패와 이전을 마무리한다. 길이 초과·중단·저장 실패, 웹과 브리지 격리, 레거시 데이터 보존, Windows·Android 배포 검증을 완료한다. 각 단계의 관련 안전 조건은 처음부터 적용한다.

### 승인할 내용과 후속 범위

이 기획은 혼합형 탐색, 작품·리더·설정 분리, HyMT2 우선 일반 텍스트 계약, 완성된 한 화 읽기, 모델과 독립된 저장, 레거시 격리를 기준으로 한다. 사용자 승인에 따라 로컬 구간 번역과 후속 작업을 진행한다. 문서 전달 자체는 코드 변경이나 이슈 정리가 완료됐다는 뜻이 아니다.

범위 지정·전체 회차 일괄 번역은 #75의 승인된 범위다. 시각적 다듬기, 작품별 용어집·말투, 웹페이지 전체 번역, 다음 화 자동 미리 번역은 별도 후속 작업으로 둔다. EPUB, 소셜 기능, 회원 계정·동기화, 앱 전용 PC 서버는 이번 범위에서 제외한다.
