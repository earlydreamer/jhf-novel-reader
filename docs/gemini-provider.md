# Gemini 구현과 현재 노출 범위

설정의 **번역 서버 → 제공자 → Google Gemini**에서 원문·작품 용어집 전송과 비용 안내를 확인합니다. **API 키**를 입력하고 **연결 확인하기**를 누른 뒤 **모델**에서 연결된 계정의 생성 모델을 선택합니다. 기본 제공자는 로컬 서버입니다.

연결을 확인한 API 키는 기기의 보안 저장소에 보관합니다. 앱 재시작과 제공자 변경 후에도 각 연결의 주소, 키 참조, 모델 선택을 기억합니다. 연결 확인은 모델 목록만 조회합니다. 자동 번역을 켠 상태에서 저장본이 없는 회차를 열면 선택한 모델로 본문을 번역합니다.

## 구현의 연결 조건

Gemini 기본 주소는 `https://generativelanguage.googleapis.com/v1beta`로 제한합니다. 다른 호스트·HTTP·포트·경로·쿼리·fragment·사용자 정보는 허용하지 않습니다.

인증값은 OS 보안 저장소의 `authRef`로 참조하고 요청 직전에 읽습니다. 모델 목록에서는 `generateContent` 지원 모델만 고릅니다. 모델 가용성·한도·가격·지역 조건과 전송 데이터 처리는 계정과 시점에 따라 달라집니다. [모델 문서](https://ai.google.dev/gemini-api/docs/models) · [가격](https://ai.google.dev/gemini-api/docs/pricing) · [데이터 처리·이용 조건](https://ai.google.dev/gemini-api/terms)

## 전체 회차 요청 계약

- 목록 조회는 고정된 `GET https://generativelanguage.googleapis.com/v1beta/models`를 사용합니다.
- Android의 본문 요청은 선택한 모델의 `:streamGenerateContent?alt=sse`를 사용합니다. 한국어 본문이 도착하면 저장 전 미리보기를 갱신합니다. 비스트리밍 모드는 `:generateContent`를 사용합니다.
- 적용할 작품 참고 정보가 없는 회차는 전체 원문을 한 번에 보냅니다. SSE는 전체 응답에 유효한 `STOP`과 번역문이 있어야 저장하며, 모델의 추론 내용은 미리보기와 저장에서 제외합니다.
- 일반 회차 번역에서 **번역 전 용어집 자동 생성**을 켜면 로컬과 같은 규칙으로 후보를 찾습니다. 생성이 필요한 경우 `:generateContent`로 구조화 응답을 받고, 원문에 있는 용어만 기존 작품 용어집에 병합합니다. 사람이 정한 표기는 보존합니다.
- 작품 용어집·말투·줄거리 참고 정보가 적용되는 회차는 로컬 스트리밍과 같은 문단 번역을 사용합니다. 각 묶음에 해당하는 표기와 별칭을 넣고 응답의 문단 순서와 필수 표기를 확인합니다. **실패한 문단 자동으로 다시 번역**을 켜면 검증에 실패했거나 필수 표기가 빠진 문단을 한 번 더 요청합니다. 응답을 확인할 수 없는 본문 요청은 다시 보내지 않습니다.
- 완료본은 `wholeChapter` 흐름에서 적용 용어집 해시와 함께 저장합니다. 제공자를 바꿔도 기존 버전을 다시 열 수 있습니다. 연결 식별자에는 제공자와 정규화한 주소를 함께 사용합니다.
- 원문과 번역본의 문단이 대응하고 스트리밍 연결을 쓸 수 있으면 독서 화면에서 문단을 골라 다시 번역할 수 있습니다. 두 제공자 모두 선택한 문단에 해당하는 작품 용어집을 적용합니다. 새 번역은 기존 본문과 합쳐 별도 버전으로 저장합니다.
- 작품 메뉴의 **용어 정밀스캔**은 두 제공자에서 같은 절차를 사용합니다. 저장된 회차 원문에서 후보와 문맥을 모으고, 선택한 모델로 묶음마다 세 번 판정한 뒤 결과를 작품 용어집에 반영합니다. 직접 고친 표기는 제안만 표시합니다. 설정에서 켠 외부 조회는 기존과 같이 용어 이름만 보냅니다.
- 제목 자동 번역과 미리 번역 후보의 **정밀스캔으로 표기 채우기**는 로컬 연결에서 지원합니다. Gemini에서도 기존 제목 저장본과 직접 편집을 쓸 수 있습니다.

## 전송과 인증 경계

API 키는 `x-goog-api-key` 헤더에만 담습니다. 키가 있는 GET은 고정 모델 목록 주소, POST는 고정 Google HTTPS `generateContent`와 `streamGenerateContent?alt=sse` 주소만 허용합니다. 스트리밍에 고정된 `alt=sse` 외의 쿼리, 다른 목적지, fragment·사용자 정보·경로 순회·Authorization 혼용은 전송 전에 거부합니다.

리디렉션은 네이티브 전송 전에 끄고 응답 URL도 비교합니다. 오류에 키나 원문을 넣지 않습니다.

## 이전 계약과 검증

`src/providers/gemini/index.ts`의 초기 `TranslationProvider` 계약은 문단 JSON을 사용했습니다. 전체 회차 구현은 `ProviderSession` 계약을 별도로 사용합니다. 두 계약을 혼용하지 않습니다.

도입 당시 검증 대상은 다음과 같습니다.

- `tests/providers/gemini/whole-chapter.test.ts`: 고정 목적지, 일반 텍스트 POST 한 번, 종료 이유 변환, 생성 가능 모델 필터를 검사했습니다.
- `tests/integration/renewal-gemini.test.tsx`: 명시적 선택과 통합 구성, Google POST 한 번, 저장본 유지, 차단·결과 불명의 미저장을 검사했습니다.
- `tests/contracts/gemini-http.test.ts`: 고정 목록 GET과 헤더 전용 키의 전송 경계를 검사했습니다.

이 검증은 모의 전송을 사용했으며 실제 Gemini 호출·실제 키·유료 요청을 사용하지 않았습니다. 현재 UI 노출 여부와 해당 테스트의 유지 여부는 현재 소스·테스트 목록을 기준으로 확인합니다. 실제 기기·계정·지역·할당량·장문 품질은 별도 승인과 검증이 필요합니다.

스트리밍 계약과 회차 통합 테스트는 합성 SSE로 미리보기, 완료 후 저장·다시 열기, 차단·출력 한도·중단·취소 시 미저장, 고정 목적지와 키 전송 경계를 검사합니다.

용어집 통합 테스트는 합성 응답으로 자동 생성과 기존 표기 보존, 별칭 주입, 미등장 용어 제외, 누락 문단만 재시도, 완료본 재열기를 검사합니다.

## Android 에뮬레이터 검증

코드 커밋 `a20ca41`을 담은 x86_64 API 36 디버그 APK에서 `gemini-3.5-flash-lite`로 공개 작품 제2~5화를 번역했습니다. 자동 생성으로 용어를 추가한 뒤 같은 회차에 적용되는 것과 자동 생성을 끈 상태에서도 기존 표기가 적용되는 것을 확인했습니다. 제5화는 LM Studio의 `google/gemma-4-e4b`로 다시 번역했습니다. 두 제공자에서 같은 원문과 동일한 용어집 해시로 두 용어가 저장 전 미리보기와 저장본의 대응 문단 여섯 곳에 반영됐습니다. 상세 결과는 [#29](https://github.com/earlydreamer/jhf-novel-reader/issues/29)에 기록합니다.

코드 커밋 `97c36a1`을 담은 같은 환경의 디버그 APK에서 제5화의 두 문단을 골라 로컬 서버와 Gemini로 각각 재번역했습니다. 두 요청의 선택 문단 입력과 적용 용어집 해시가 일치했습니다. 지정 표기 두 개를 저장 전 스트리밍 미리보기와 각 저장본에서 확인했습니다. 나머지 106개 문단과 기존 저장본, 용어집 24개 항목을 보존했고, 네트워크를 끄고 앱을 다시 실행해 Gemini 재번역본을 열었습니다.
