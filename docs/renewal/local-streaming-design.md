# 로컬 스트리밍 독서 경로

2026-10-08 사용자가 기존 방식을 옵션으로 남기고 콜로모식 스트리밍을 구현하도록 요청했다. [콜로모](https://syosetu.colomo.dev/)의 현재 공개 번들은 SSE를 읽고 줄 ID로 표시하며 직전 번역을 이어 붙인다. 클라우드의 큰 입력 크기를 그대로 로컬에 옮기지 않는다. [llama.cpp 서버](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)의 OpenAI 호환 스트리밍을 사용한다. 모델별 VRAM 수치는 사용자가 붙인 리서치의 가설이며 이번 앱 변경이 8GB 장비에서의 실제 메모리 사용을 증명하지 않는다.

## 사용자 흐름과 호환성

- Android 로컬 모델의 새 기본은 **읽으며 번역**, 설정에서 **기존 묶음 번역**을 선택할 수 있다. 이전 저장본·배치·설정은 계속 읽는다. Gemini는 기존 경로다.
- **저장본이 없으면 자동 번역 시작**은 기본 켜짐이며 설정에서 끌 수 있다. 끄면 ‘이 화 번역’으로 시작한다. 저장본 읽기·앱 시작·설정의 모델 목록 확인만으로는 번역 요청을 보내지 않는다. 선택한 회차가 바뀌거나 요청 결과가 미확정이면 자동 시작하지 않는다.
- 번역을 시작하면 독서 영역에 도착한 문단부터 표시한다. 청크 응답이 끝나기 전에도 출력이 보인다. 태그는 HTML로 실행하지 않으며 원문 문단 순서·빈 문단을 보존한다. 읽는 동안 새 문단이 생겨도 강제로 맨 아래로 이동하지 않는다.
- 완료 후 같은 본문에서 목차·이전 화·다음 화·원문·글자 크기를 바로 사용한다. 추가로 ‘저장본으로 읽기’를 누를 필요가 없다. 빠른 스크롤의 위치 저장은 진행 중인 저장과 최신 위치로 합쳐 회차 조회가 밀리지 않게 한다. 회차를 불러오는 중에는 상태를 표시하고 이동 버튼 중복 입력을 막는다.
- 저장 전 결과와 실패한 원문을 명시한다. 취소·통신 단절·백그라운드 전환 시 서버 결과는 미확정으로 취급하고 자동 재전송하지 않는다. 읽던 위치는 완성본으로 전환할 때 이어받는다.

## 로컬 루프

1. 컨텍스트 상한은 서버 보고 용량과 8192 중 작은 값이다. 전체 입력(지시·노트·요약·직전 원문/번역·청크)을 추정하고 출력·템플릿 여유를 예약한다. VRAM을 바꾸거나 서버 컨텍스트를 늘리지 않는다.
2. 비공백 문단 8개로 첫 결과를 빨리 내고, 이후 최대16개씩 묶는다. 한 문단 ID는 분할하지 않는다. 큰 문단은 단독 요청으로 보내고 그래도 안 들어가면 입력 한도 오류로 표시한다. 히스토리를 먼저 버리고 새 청크 크기를 줄인다.
3. 요청은 `<main><p id="...">...</p>...</main>` 계약이다. 응답 ID의 개수·순서·중복과 끝 태그를 검증한다. 직전 청크의 원문/번역 한 쌍만 히스토리로 보내며, 작품 용어집·말투는 이번 원문 등장분만 노트로 넣는다.
4. 사용자가 확정한 작품 용어는 `__ENT_n__`으로 가리고 한국어 표기로 복원한다. 임시 토큰은 원문과 충돌하지 않게 만들고, 반환 누락·변조를 검증한다. 프리셋의 일반 설정 어휘는 마스킹하지 않는다.
5. **실패 문단 자동 재시도**도 기본 켜짐이며 별도 설정으로 끌 수 있다. ID/가나/잠근 표기 검사 실패는 실패한 문단만 한 번 다시 요청하고 이미 승인된 문단은 유지한다. ID 계약 전체가 깨졌으면 전체 청크가 실패 대상으로 남는다. 재시도 후에도 문제인 줄은 원문을 표시하고 실패 문단 번호를 저장한다. 네트워크 결과 불명·인증 오류는 자동 재시도하지 않는다.
6. 이전 화 요약은 선택적인 작품 메모(최대400자)로 받으며 용어 이름을 제외해 주입한다. 자동 요약 생성은 추가 모델 작업이므로 이 버전에서 실행하지 않는다. 직전 청크 문맥은 실행 중에만 유지한다.

## 저장본의 문단 재번역

독서 화면에서 실패 문단 전체 또는 문단 하나를 골라 수동으로 다시 번역한다. 현재 로컬 모델과 작품 용어를 사용하고 선택하지 않은 문단은 요청에서 제외한다. 원문과 번역 문단이 1:1인 저장본에만 허용한다. 저장된 원문으로 실행하므로 원문 재수집 없이 문단 위치를 유지한다.

결과는 이전 저장본을 덮어쓰지 않고 새 버전으로 저장한다. `provenance.repair`에 이전 버전 ID와 재번역 문단 번호를 기록한다. 실패한 문단의 기존 내용과 다른 정상 문단은 유지하고, 저장 실패는 모델 요청 없이 저장만 재시도한다. 수동 문단 재번역은 기존 묶음 번역 옵션의 선택값을 바꾸지 않는다.

문단 재번역의 통신 결과가 미확정이면 명시적 재시도도 같은 문단 범위를 유지한다. 긴 문단 선택 문구가 휴대폰의 화면 폭을 늘려 터치 좌표가 어긋나지 않도록 입력·선택 컨트롤은 부모의 폭 안에 제한한다.

## 전송과 검증

기존 CapacitorHttp는 완성 응답만 반환하므로 새 Android SSE 플러그인을 추가한다. 서버 요청은 하나씩, 리다이렉트는 전송 전 비활성화, 인증은 헤더만 사용한다. 취소 시 소켓을 닫되 Promise가 실제 정리된 뒤 다음 요청을 허용한다. 웹 fetch로 CSP·네이티브 경계를 우회하지 않는다.

검증은 분할 SSE/UTF-8·ID 경계·중복·줄 합치기·재시도 상한·가나·잠근 이름·입력 예산·히스토리 버리기·기존 모드/저장 호환·취소 후 동시 요청0·독서 위치를 포함한다. 기기에서는 실제 SSE 첫 표시 시간과 마지막 저장 시간을 따로 측정하고, 응답이 끝나기 전에 화면에 텍스트가 나타났는지 확인한다. 소설 전문·모델 요청·사설 주소는 private 작업 폴더에만 둔다.
