# Linux Hy-MT2 구간 번역의 실제 회차 검증

사용자가 승인한 #74 컨텍스트 분할과 #75 일괄 번역 구현으로 실제 회차를 다시 확인했다. 한 번 시작한 작업이 전체 원문을 순서대로 보내고 모든 응답의 저장이 끝난 뒤 읽는 계약이다. 2026-10-05의 한 POST 실험과 분리한다. 결과는 **전송·저장·오프라인 복원 PASS, 의미 보존 FAIL**이며 #72가 남는다.

## 소스와 실행 조건

- 테스트 구현: `1701f700b88681b24bcb8ba5d138a9bb7d3ca2c1`. app APK SHA-256 `546b10a02a5934d98679305a842d2804a0520384115b081784bfd4fed095117f`.
- 기기: Black Shark 2 SKW-H0, Android 10 / API 29. 사용자 파일을 지우거나 제거 재설치하지 않았다.
- Linux engine: llama.cpp build 11146, commit `7fe450e19305b828c199d602c23a8337aaa1f03b`, CUDA, GPU layers 16. 기존 Gemma 서버는 유지했다.
- [공식 모델](https://huggingface.co/tencent/Hy-MT2-7B-GGUF): `Hy-MT2-7B-Q4_K_M.gguf`, revision `ab8472660ac61fac25f1af43fac2599d52a8a775`, 4,624,648,896 bytes. 다운로드 SHA-256 `9f96256500f3fc1ab4d64336b58f52a949a95ad7516b0c229476eef782f9f77b` 확인.
- 서버 context 8,192, 앱 입력 예산 2,048, 출력 한도 4,096 tokens. 서버 temperature 0.7, top-k 20, top-p 0.6, min-p 0, repeat penalty 1.05.
- 사용자 지정 `n6517bw` 3화의 정규 원문 7,258자, 비공백 원문 문단 103개. 원문·응답·사설 주소·인증값은 공개 저장소에 넣지 않는다.

출력 비공백 블록도 103개지만 문단 수 일치는 품질 근거가 아니다. 14구간을 처음부터 끝까지 대조했을 때 과거의 큰 중간 누락은 이번 결과에서 발견되지 않았으나 다음 의미 오류가 남았다.

- 상대 기간이 달력의 특정 월로 바뀐다.
- 신체 능력, 높이와 방향, 무기 없는 행동의 의미가 바뀐다.
- 유능·무능 대비가 사라지고 양쪽을 같은 뜻으로 옮긴다.
- 관용구와 루비의 의미를 그대로 합친 명사처럼 출력한다.
- 물건·나무 종류, 대사 의도와 인명 표기가 흔들리며 일부 일본어와 수량의 오류가 남는다.

## 원인 분리 후속

같은 실패 구간에 temperature 0, 공식 최소 prompt, 일본어·영어 의미 보존 prompt를 각각 적용했다. 영어 지침이 대비 표현 하나를 개선했지만 기간·관용구 문제는 남았다. 원래 지침으로 문제 문단만 보내 입력 118–181 tokens까지 줄인 진단에서도 기간과 관용구가 틀렸다. 대비 표현은 문단 단독 요청에서 개선됐다.

따라서 이번 오류 전체를 context 초과로 설명할 수 없다. 구간 분할은 큰 누락을 줄였지만 작은 입력에서도 남는 모델의 어휘·의미 해석 오류가 있다. 충분히 해결되지 않은 prompt를 production에 교체하거나 같은 조건의 전체 회차 요청을 반복하지 않았다. [#72](https://github.com/earlydreamer/narou-reader/issues/72)를 유지하며 #74/#75/#21 구현·저장 검증과 G1의 실제 의미 보존을 구분한다.

초기 CPU sidecar 시도는 검증 harness의 15분 제한에서 9개 응답 뒤 중단되어 전체 회차 품질 결과가 아니다. GPU 실행은 별도 증거 경로에서 끝까지 완료했고 위 결과는 그 실행만 사용한다. 모델의 HTTP 200·stop·EOS·동일 문단 수로 G1 성공을 선언하지 않는다.
