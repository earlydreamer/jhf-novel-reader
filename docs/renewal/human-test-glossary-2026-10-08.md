# 용어집 범위 스캔·확정·번역 직접 테스트

2026-10-08 사용자 요청에 따라 남은 파이프라인을 순차 구현했다. PR #81은 Draft로 유지하고, 결과물의 문장 의미·말투와 사용 흐름을 사람이 직접 확인한다. 자동 확인 표시는 품질 합격 판정이 아니다.

Black Shark 2에는 **나로우 리더 · 테스트**를 설치하고 E4B 연결과 실제 회차 1개의 저장본을 준비했다. 독서 화면이 열려 있으므로 먼저 읽어볼 수 있다. 이번 실제 결과는 가나 잔존 0문단, 확정 표기 미발견 1개이며, 새 후보 19개의 표기는 자동 등록하지 않았다. 후보 확정 흐름은 아래 절차로 직접 시험하면 된다.

## 시작

기존 설치 앱과 저장본을 보존하기 위해 별도 Android 패키지 `app.narou.reader.proof80`를 사용한다. 앱 이름은 **나로우 리더 · 테스트**다. 실제 설정 주소와 소설 원문·번역 전문은 공개 문서에 기록하지 않는다. 테스트 앱의 설정은 기존 앱과 독립적이다.

1. 테스트 앱을 열고 설정에서 연결 확인 후 사용할 E4B 모델을 고른다. 모델 목록이 확인된 상태에서 작품을 연다.
2. 먼저 1–2화 정도의 작은 범위를 선택하고 **범위 확인**을 누른다. 제목과 선택 범위, 기존 저장본 개수를 확인한다.
3. 작품 용어집에서 직접 편집한 항목이 있으면 저장한 뒤 **범위 고유명사 후보 스캔**을 누른다. 스캔 진행 중 모델 번역은 시작하지 않는다.
4. 후보에서 인명·지명 등 사용할 항목만 선택해 한국어 표기를 입력하고 **선택한 N개 표기 확정**을 누른다. 루비 읽기, 등장 횟수와 회차 수가 판단에 도움이 되는지 본다. 후보가 없거나 모두 일반 단어면 후보를 사용하지 않고 확인을 마칠 수 있다.
5. **확인한 회차 번역 시작**을 누른다. 각 회차가 순서대로 저장되고 진행 중 새 후보 확인 창이 뜨지 않는지 본다. 중단한 뒤에는 남은 회차만 명시적으로 재개한다.
6. 목차에서 저장된 회차를 열어 읽는다. **번역 확인**을 펼쳐 가나 잔존 문단 버튼으로 이동하고, 확정 표기 미발견 항목을 원문과 비교한다. 원문 보기와 번역 보기 전환, 글자 크기와 읽던 위치도 확인한다.
7. 앱을 닫았다 다시 열어 저장본을 읽는다. 확인 표시가 유지되는지 본다. 연결 없이 읽는 경우에도 저장본을 사용한다.

## 판단할 내용

- 인물 이름·별칭·호칭이 문맥에 맞고 회차 사이에서 일관적인가?
- 대화 말투와 화자·주어가 자연스러운가? 생략된 주어를 잘못 보충하지 않았는가?
- 원문 첫 문단부터 마지막 문단까지 의미가 보존되는가? 기간 표현, 관용구, 설정 어휘에 오역이 남는가?
- 후보에 일반 단어가 너무 많이 섞이거나 필요한 인명이 빠지는가? 후보 선택·표기 입력 흐름에 불편이 있는가?
- 확인 표시가 읽기에 도움이 되는가? 가나나 표기의 부재가 의도된 경우도 있으므로 표시만으로 오역을 확정하지 않는다.

가나 확인은 한자만 남은 일본어를 찾지 못한다. 표기 확인은 번역 전체에서 한 번이라도 확정 표기가 나오면 표시하지 않으므로 일부 등장분의 오표기를 놓칠 수 있다. 모델 응답이나 저장된 본문을 자동으로 수정하지 않으며 품질을 이유로 추가 생성 요청을 보내지 않는다.

불편·오역은 회차와 문제 유형을 적어 전달하면 된다. 공개 GitHub·Vault에는 소설 원문·번역 전문 대신 문제 유형, 위치와 지표만 남긴다.
