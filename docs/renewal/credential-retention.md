# 인증값 보존과 회수 (#299)

서버 인증값을 바꾸거나 연결 주소를 바꿔도 이전 키를 즉시 지우지 않습니다. 진행 중인 요청은 이전 설정을 이미 잡아 두었을 수 있고, 일시정지한 미리 번역 작업은 원래 인증 참조로 다시 시작합니다.

## 회수 시점

앱의 JavaScript 실행 환경이 새로 시작되고 네이티브 백업 복구가 성공한 뒤, 컨트롤러와 요청을 만들기 전에 한 번만 확인합니다. 같은 JavaScript 실행 중에는 다시 회수하지 않습니다. 운영체제 프로세스의 수명과는 다르며, 전체 WebView 새로고침도 새 실행 환경입니다. 앱이 실행 중일 때 교체되어 참조가 끝난 키는 다음 시작까지 남습니다. 컨트롤러를 닫거나 새로 만드는 것만으로는 키를 삭제하지 않습니다.

기기의 보안 저장소에서 앱 전용 접두사 아래의 `provider.<v4 UUID>` 키 이름만 열거합니다. 비밀값을 읽거나 로그에 남기지 않습니다. 다음 참조는 보존합니다.

- 실제로 저장된 설정의 인증 참조. 화면의 임시 설정으로 대체하지 않습니다.
- 미리 번역 기록의 두 복구 슬롯에 있는 모든 인증 참조. 이전 슬롯, 완료한 기록, 안내를 닫은 기록도 포함합니다.
- 다른 이름 형식의 키와 레거시 키.

설정·작업 기록을 읽지 못하거나 알 수 없는 형식·손상된 복구 슬롯이 있으면 정리하지 않습니다. 키 목록 확인 또는 삭제가 실패해도 저장본 읽기를 막지 않고 다음 시작 때 다시 확인합니다. 삭제 실패 지점 이후의 키는 남습니다. 설정 저장 실패로 예전 설정이 남아 있으면 그 키도 남습니다.

## 백업과 복원

백업에는 API 키가 포함되지 않으며 복원 후에는 인증값을 다시 입력해야 한다는 기존 정책을 유지합니다. 외부 ZIP 파일에 남은 인증 참조가 기기 키의 영구 보존을 보장하지 않습니다. 이전 백업을 복원했는데 미리 번역 작업의 키가 이미 없으면, 연결 설정에서 인증값을 입력하고 모델을 확인한 뒤 번역 범위를 명시적으로 다시 준비해야 합니다. 저장된 작업의 서버·모델·인증 참조를 새 설정으로 자동 변경하거나 요청을 몰래 재전송하지 않습니다.

중단된 복원은 네이티브 복구가 설정과 파일을 함께 복구하고 임시·이전 트리를 정리한 뒤에만 키 정리에 진입합니다. 복구가 실패하면 키 정리와 앱 시작 모두 진행하지 않습니다.

## 검증 범위

합성 키 이름과 메모리 저장소로 설정 교체, 두 복구 슬롯, 모든 작업 단계, 손상·미래 형식·I/O 오류, 삭제 실패, 시작 순서 및 동일 실행 중 재정리 방지를 검사합니다. 실제 사용자 인증값의 열람·삭제나 기기 실행은 포함하지 않습니다.
