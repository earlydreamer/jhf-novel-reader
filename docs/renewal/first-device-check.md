# G1: 첫 한 화의 실제 처리와 의미 보존 확인

2026-10-07 상태: **의미 보존 FAIL**. 최신 [Linux Hy-MT2 구간 검증](hy-mt2-segmented-g1-2026-10-07.md)은 전체 입력 처리·저장·오프라인 복원을 통과했지만 모델 의미 오류가 남았다. 이 문서는 재검증 절차이며 과거 VM의 NOT RUN 상태를 현재 기기 상태로 제시하지 않는다. 사용자는 후속 구현과 #74/#75 진행을 승인했다. 합성 테스트·JVM 테스트·APK 감사와 실제 번역 품질을 구분한다.

## 준비

- 전달된 APK의 커밋과 SHA-256을 결과표에 적고 일치하는 파일만 설치한다. 기존 독서 데이터가 있으면 앱 데이터 삭제·제거 재설치를 먼저 하지 않는다.
- 우선 기기: 사용자가 이전에 사용한 SM-F966N / Android 16. 실제 사용한 모델명·OS·WebView 버전도 적는다.
- 현재 검증은 사용자가 지정한 Linux 서버의 기존 engine과 별도 Hy-MT2 모델을 사용한다. Windows LM Studio 결과는 별도 증거로 유지한다. 휴대폰에서 닿는 Tailnet/IP 주소를 앱에 입력하되 공개 보고서·스크린샷에 사설 주소나 인증값을 남기지 않는다.
- 서버의 실제 모델 목록에서 HyMT2 7B를 선택한다. 서버 버전·정확한 모델 ID/양자화·context와 출력 한도를 기록한다. #74의 내부 예산으로 전체 원문을 순서대로 나누며 참고 데이터도 입력 예산에 포함한다. 사용자가 토큰 값을 직접 입력하지 않는다.
- 원문 접근·번역·저장이 허용된 회차로만 확인한다. 권한·이용 조건이 불명확하거나 제한을 만나면 해당 실호출을 멈추고 NOT RUN으로 남긴다. 로그인/연령/접근 제한을 우회하지 않는다.

## 짧은 휴대폰 체크리스트

1. 홈의 **나로우에서 작품 찾기**를 누른다. 앱 안에서 사이트의 실제 검색·랭킹·분류 중 하나로 허용된 작품을 찾고, 탐색 뒤로 가기도 확인한다. **이 작품 열기**를 눌러 제목과 목차를 연다. URL 붙여넣기나 합성 HTML만으로 이 항목을 PASS 처리하지 않는다.
2. 첫 화가 아닌 원하는 회차를 선택한다. 번역 전 작품/회차 제목을 확인한다. 작품·목차 열기와 모델 목록 GET은 생성 POST가 아니며, 이 시점에는 본문 선조회·생성이 없어야 한다.
3. 설정에서 주소와 필요한 경우에만 인증값을 입력한다. **연결 확인**으로 실제 목록을 가져와 HyMT2 7B를 선택한다. 원래 회차로 돌아와 **이 화 번역**을 누른다. 연속 탭은 두 번째 작업을 만들지 않는다. #74에 따라 계획한 구간 수만 순차 요청하며 자동 재전송·다른 제공자 전환은 없다.
4. 전체 한국어 결과가 기기에 저장된 다음 리더에 나타나는지 확인한다. 일부 결과를 미리 표시하거나 JSON 출력·문단 ID·추가 보정 호출을 요구하면 FAIL이다. 계획한 구간 수·실제 POST 수·최대 동시 요청·context 안의 실제 토큰을 기록한다. 원시 본문·헤더·비밀값을 공개 로그에 넣지 않는다.
5. 첫 문장부터 끝까지 읽고 순서·숫자·반복 문장·대사·빈 줄·루비 의미의 누락/중복을 확인한다. 문단 수 차이만으로 실패로 판정하지 않되 의미 누락은 따로 적는다. 원문이나 번역 본문은 검증 로그에 복사하지 않는다.
6. 모델 서버 연결을 끊고 앱을 다시 열어 홈의 이어 읽기로 같은 저장본을 읽는다. 새 모델 요청 없이 읽혀야 한다. 저장 경로는 앱 전용 내부 파일이며, 화면 이동·모델 변경으로 삭제되지 않아야 한다.
7. 아래 네이티브 경계 fixture를 실제 기기에서 실행한다. 앱 안의 실제 발견과 경계 테스트가 모두 PASS일 때만 G1을 통과한다.

## 네이티브 경계와 중단 확인

별도 androidTest APK는 컴파일된 검증 fixture이다. 전달받은 정확한 테스트 APK로 `SourceBrowserInstrumentedTest`를 기기에서 실행하고 개별 결과를 적는다. 과거 다른 APK의 실행을 새 APK에서 재실행한 것으로 바꾸지 않는다.

- 허용된 HTML 링크와 GET 검색은 production WebViewClient를 거쳐 이동한다.
- 메인 문서·이미지·iframe의 리다이렉트도 동일 경계 검사를 거친다.
- HTTPS 외부 주소는 사용자 동작에 따른 명시적 외부 브라우저 열기만 제공한다. 앱 안에서 직접 로드하지 않는다.
- file/content/intent/javascript/custom scheme, 위조 bridge 메시지, 쿼리로 위장한 선택 URL, POST/download/권한 요청은 거절된다.
- 브라우저에는 Capacitor/비밀값/모델 호출 bridge가 없고, activity는 nonexported AppCompatActivity이다.
- JavaScript 비활성 후보에서 실제 검색·랭킹·분류가 안 되면 막힌 기능/목적지를 기록하고 FAIL로 멈춘다. JS나 허용 호스트 범위를 임의로 넓히지 않는다.
- 번역 대기 중 기기 대기 중단·백그라운드·화면 변경이 새 요청을 만들지 않는지 확인한다. 취소는 서버 작업 종료를 보장하지 않는다. native 응답이 끝나기 전 새 요청이 겹치면 FAIL이다.
- 앱 종료 뒤 결과 불명 상태는 사용자가 중복 처리 위험을 읽고 명시적으로 다시 누르기 전 재전송하지 않는다.
- 저장 실패를 재현할 때는 보존된 결과의 **모델 요청 없이 저장 다시 시도**만 사용한다. 기존 데이터를 지워 저장 실패를 만들지 않는다.

## 중지 조건

G1에서 의미 보존이나 안전한 네이티브 발견이 실패하면 관련 이슈에 결함과 실행 조건을 기록하고 새 근거가 있는 영향 경로만 재검증한다. 후속 구현은 사용자의 진행 승인 범위에서 계속할 수 있지만 실패한 품질 게이트를 통과로 보고하거나 공개 배포 근거로 삼지 않는다. Linux·Windows LM Studio·Ollama 결과는 별도로 유지하며 미실행 제공자는 NOT RUN으로 남긴다.
