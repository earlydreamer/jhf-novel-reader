# 범위·전체 회차 일괄 번역

관련 이슈는 #75이며, 한 화 분할 번역 #74 위에서 같은 `WholeChapterFlow`를 순차 사용한다. 작품 화면에서 범위 또는 전체 회차를 확인하고, 확정한 범위·회차 수·모델·기존 완성본 수를 읽은 뒤 별도 동작으로 시작한다. 범위 양 끝을 포함하며 최대 10,000화까지 한 작업에 담는다.

대상 확인은 작품의 첫 목차부터 마지막 목차까지 연결을 따라간다. 순환 링크·다른 작품·중복 회차·회차 누락·잘못된 범위는 거부하며, 모두 연결해 확인한 뒤에만 전체 목차로 저장한다. 이 단계에서 본문 생성 요청은 없다.

제공자·서버·모델·인증 참조·내부 예산을 확정하고 순서대로 처리한다. 기본적으로 같은 제공자·모델의 완성본을 건너뛴다. 재번역은 별도 선택이며 기존 버전은 보존한다. 모델 목록의 재조회처럼 유효 설정이 같은 동작은 재개를 막지 않지만, 서버·모델·인증 참조·예산이 달라지면 대상을 다시 확인해야 한다. 일괄 실행 중에는 설정 변경·중복 시작·개별 번역 시작을 차단한다.

각 회차는 완성본만 저장한다. 저장 완료 후 다음 회차로 진행하고 리더로 자동 이동하지 않는다. 취소·백그라운드 중단·길이 제한·실패·결과 불명에서는 이후 요청을 보내지 않는다. 저장 실패는 기존 한 화 흐름의 결과를 보존하고, 저장 재시도에서 생성 요청을 추가하지 않는다. 저장을 마친 뒤에도 다음 회차는 직접 재개한다.

대기열은 앱 내부의 `batches/current` 두 슬롯 저널에 저장하며 최신 한 작업만 유지한다. 회차 진입 전에 기존 버전 ID와 실행 상태를 기록한다. 재실행 시 진입 여부가 확인되는 미전송 경계는 중단 상태로, 전송 여부가 불명인 경계는 결과 불명으로 복구한다. 어느 경우에도 자동으로 요청하지 않는다. 결과 불명 상태에서는 중복 처리 가능성을 안내하고 명시적 재개를 받는다. 이미 새 완성본이 저장됐지만 대기열 갱신이 실패한 경우에는 기존 버전 ID와 비교해 저장을 확인하고 다시 생성하지 않는다. 손상되거나 지원하지 않는 저널은 새 번역을 차단한다.

합성 통합 검증은 다페이지 범위·전체 회차, 순서와 최대 활성 요청 수, 완성본 건너뛰기와 재번역, 오류·취소·백그라운드, 저장 재시도, 상태 저장 실패, 재실행 경계와 손상 기록을 다룬다. 실제 기기 UI·네이티브 저장·리눅스 모델 요청 결과는 별도 증거로 기록하며, 합성 데이터 통과를 실제 소설의 번역 충실도 통과로 사용하지 않는다.
