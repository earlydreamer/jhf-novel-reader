# 후속 작업 우선순위와 단계별 설계

현재 앱의 중심인 로컬 모델 번역과 독서 흐름을 우선하여, **용어집 접근성 개선 → 별명 판정 비교 실험 → ChatGPT Android 연결 검증** 순서를 제안합니다. Gemini는 기존 보류 결정을 유지합니다. 각 작업은 독립적으로 검증하고 전달하며, 한 작업의 미완료를 다른 작업의 일괄 차단 조건으로 삼지 않습니다.

이 설계는 [설계 이슈 #328](https://github.com/earlydreamer/jhf-novel-reader/issues/328)에서 관리합니다. 2026-10-15 기준 `main`의 `e1562761703bc93f4183cafedb54f97b8fb232b7`과 열린 네 이슈의 본문·댓글을 대조했습니다. 아래 단계는 구현 제안입니다. 이 문서의 전달만으로 기존 후순위·보류 결정을 해제하거나 제품 기능을 지원 상태로 바꾸지 않습니다.

이 순서는 현재 기능을 찾고 고치는 데 드는 불편, 로컬 번역 품질, 외부 제공자 확대 순으로 판단한 제안입니다. #147은 기존에 후순위였으므로 이번 설계 검토에서 다음 구현 대상으로 선택해야 착수합니다. #219와 #307은 #147의 기술적 결과를 기다릴 필요는 없지만, 동시에 여러 기능을 구현하는 계획으로 해석하지 않습니다.

## 용어집 접근성 개선

### 현재 동작과 목표

작품 화면의 `⋮ → 용어집 편집하기`는 [GuidancePanel](../src/ui/GuidancePanel.tsx)을 전체 화면 대화상자로 엽니다. 리더는 [TermEditor](../src/ui/TermEditor.tsx)와 [useReaderGlossary](../src/ui/readerGlossary.ts)로 문단의 용어 추가·편집·삭제를 지원합니다. #147의 리더 개별 용어 편집 후보는 #265에서 이미 구현했으므로 다시 만들지 않습니다.

다음 기능의 목표는 **작품 화면에서 용어집을 바로 찾고, 읽던 화면에서도 전체 용어집을 고친 뒤 같은 위치로 돌아오는 것**입니다.

### 단계별 변경

1. 작품 화면의 작품 정보 아래, 회차 목록 위에 `용어집 편집하기` 텍스트 버튼을 표시합니다. 기존 메뉴 진입도 같은 편집기를 엽니다. 용어 정밀스캔과 혼동하지 않도록 편집 버튼에서 스캔이나 모델 요청을 시작하지 않습니다.
2. 리더의 `더보기` 메뉴에 같은 행동을 추가합니다. 작품 목차로 이동하지 않고 현재 리더 위에 전체 화면 편집기를 엽니다. 닫을 때 현재 회차·번역 버전·원문 보기·스크롤 위치를 유지합니다.
3. 작품과 리더가 전체 용어집 대화상자를 공유하도록 기존 `WorkScreen`의 래퍼를 추출합니다. 용어·별칭·말투·이야기 요약을 편집하는 `GuidancePanel`과 기존 저장 검증을 재사용합니다. 별도의 용어 저장소나 새 화면 경로를 만들 필요는 없습니다.
4. 저장 성공 시 반환된 용어집 hash를 갱신 신호로 전달하여 리더 강조와 개별 편집 데이터가 다시 읽히게 합니다. 실패하면 입력 초안을 유지하고 저장 완료 안내를 표시하지 않습니다.

구현의 주요 연결 지점은 [Application](../src/app/Application.tsx)의 화면 조립과 용어집 훅, [WorkScreen](../src/ui/WorkScreen.tsx)의 직접 진입, [ImmersiveReader](../src/ui/ImmersiveReader.tsx)의 메뉴, [renewalController](../src/app/renewalController.ts)의 `readGuidance`·`saveGuidance`입니다. 기존 대화상자의 뒤로가기 처리와 초점 복귀를 유지합니다.

### 편집 상태와 데이터 보존

- 열 때 현재 작품 ID와 용어집을 확인합니다. 읽기 실패를 빈 용어집으로 간주하여 덮어쓰지 않습니다.
- 번역·일괄 처리·정밀스캔 등 기존 저장 가드가 막는 작업 중에는 읽기만 허용하고 변경·저장을 막습니다. UI의 잠금 상태를 컨트롤러의 실제 거부 조건과 맞춥니다. 읽던 번역을 편집기 진입 때문에 취소하지 않습니다.
- 초안에 변경이 있을 때 닫기·Android 뒤로가기는 변경을 버릴지 확인합니다. 저장 중에는 중복 제출을 막습니다. 작품이 바뀌거나 최신 용어집이 다른 작업으로 바뀐 경우 오래된 초안을 자동 저장하지 않습니다. 충돌 시 초안을 보존하고 다시 읽을 수 있게 합니다.
- 저장한 변경은 다음 번역부터 적용합니다. 기존 번역 본문과 읽기 위치는 그대로 보존하며, 편집기에서 닫기나 저장만으로 재번역을 요청하지 않습니다.

### 완료 조건과 검증

작품 화면과 리더에서 동일한 작품 용어집을 열고 저장·재열기까지 확인합니다. 빈 용어집, 저장 실패, 작업 중 잠금, 변경 취소, 반복 저장, 다른 작품으로 이동, 저장 뒤 강조 갱신을 합성 UI·통합 테스트로 검사합니다. 기존 `guidance-panel`, `reader-glossary`, `immersive-reader` 테스트를 확장하고 기본 프로젝트 검사를 실행합니다.

Android에서는 편집기를 열고 닫은 뒤 실제 읽기 위치가 유지되는지, 뒤로가기와 키보드가 동작하는지, 좁은 화면과 라이트·다크 테마에서 직접 진입을 찾을 수 있는지 확인합니다. 테스트 통과와 기기 검증을 구분하여 기록합니다.

### 앱 공통 용어집의 후속 범위

공통 용어집은 여러 작품의 번역 결과와 저장 형식에 영향을 주는 독립 기능이므로 #147의 접근성 구현에 포함하지 않습니다. 구현을 선택하면 별도 이슈에서 다음 계약을 먼저 확정합니다.

- 기본 합성안은 `작품별 명시적 제외 → 작품별 표기 → 공통 표기` 우선순위입니다. 작품의 자동 생성 항목과 사람이 정한 공통 항목이 충돌하는 경우도 별도로 정의합니다.
- 원문과 별칭을 정규화한 충돌, 공통 항목의 작품별 제외, 같은 이름을 다른 뜻으로 쓰는 경우를 처리합니다.
- 공통 항목 편집 뒤 기존 저장본은 유지하고 다음 번역의 출처·캐시 식별에 유효 용어집 hash를 반영합니다.
- 백업 형식, 이전 백업 복원, 공통 항목 삭제와 작품별 덮어쓰기 보존을 함께 설계합니다.

## 별명 판정 비교 실험

### 현재 동작과 가설

[termScanRun](../src/translation/termScanRun.ts)은 후보를 묶어 외부 조회한 뒤 세 번 판정하고 다수결을 냅니다. [termJudge](../src/translation/termJudge.ts)는 후보 문맥·루비·한자 힌트·조회 결과를 판정 요청에 넣습니다. 현재는 음독 의심 결과의 신뢰도를 낮추는 보호 장치가 있습니다.

#219의 가설은 별명 후보에 한하여 **구성 글자의 뜻 → 가리키는 대상 → 뜻으로 옮긴 표기**를 한 번 먼저 정리하면 최종 판정이 개선될 수 있다는 것입니다. `の`가 있다는 사실만으로 별명으로 확정하지 않습니다. 사람·작품·지명에 포함된 반례를 비교군에 넣습니다.

### 단계별 실험

1. 합성 데이터로 별명 12건과 일반 이름·작품명 등 반례 8건을 준비합니다. 기대 표기와 허용 가능한 대안을 실행 전에 검토합니다. 이슈의 짧은 재현 이름은 포함할 수 있지만 실제 소설 문단을 공개 자료에 넣지 않습니다.
2. 같은 모델·양자화·서버 설정·문맥·외부 조회 응답을 고정하고 기존 방식과 실험 방식을 각각 세 차례 실행합니다. 비교 단위는 현재의 세 번 판정을 모두 마친 스캔 결과입니다. 추가로 사용 가능한 큰 모델 비교는 보조 자료로 두고 필수 조건으로 삼지 않습니다.
3. 실험 방식은 해당 후보마다 추가 뜻 분해 요청을 최대 한 번만 보냅니다. 엄격한 JSON으로 `parts`, `referent`, `rendering`을 받고 후보 식별자·길이·형식을 검증한 뒤 최종 판정에 참고 자료로 넣습니다. 이를 검증된 외부 근거로 취급하지 않습니다. 원래 세 번 판정마다 뜻 분해를 반복하지 않습니다.
4. 추가 요청이 실패·부적합이면 기존 판정으로 진행하고 기존 신뢰도 완화 장치를 유지합니다. 사용자가 취소하거나 요청 결과가 불명인 경우에는 진행을 중단하고 자동 재전송하지 않습니다. 추가 단계는 제품에 기본 활성화하기 전에 독립 실험 경로로 비교합니다.
5. 의미 표기의 정확도, 분류 오판, 사람 항목 덮어쓰기, 추가 요청 수, 완료 시간과 취소 동작을 비교하여 채택·수정 실험·중단 중 하나로 결론 냅니다.

### 채택과 중단 기준

초기 채택 기준은 원래 재현 사례의 올바른 표기가 세 차례 모두 나오고, 별명 12건의 최종 정답 수가 세 실행 합계에서 기존보다 늘며, 반례의 잘못된 별명 판정과 사람 항목 덮어쓰기가 증가하지 않는 것입니다. 요청은 대상 후보당 한 번을 넘기지 않고 전체 완료 시간의 중앙값 증가는 기준 방식의 50% 이내를 목표로 합니다. 이 시간 기준은 측정값이 아니라 실험 전에 정할 초기 허용치입니다.

정답 개선이 없거나 반례가 악화되면 기본 기능에 넣지 않습니다. 정확도는 개선되지만 시간 기준을 넘으면 자동 적용을 보류하고 선택 실행 등 범위를 다시 검토합니다. JSON 검증·대상 제한·취소·요청 횟수는 합성 테스트로 확인하고, 번역 의미 개선은 실제 모델 비교 결과로 판정합니다. 결과는 #219에 요약하며 모델 원시 출력은 공유하지 않습니다.

## ChatGPT Android 연결 검증

### 공식 경로와 현재 구현의 차이

2026-10-15 확인한 공식 문서는 시스템 브라우저에서 인증한 뒤 `127.0.0.1` HTTP 콜백을 받도록 요구합니다. 이 조건만으로 Android 지원이 입증되지는 않으므로 앱 생명주기와 브라우저 왕복을 첫 검증 대상으로 둡니다. [공식 등록과 로그인](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)

추론은 계정별 모델 목록과 `POST /v1/responses`, `stream: true`, `store: false`를 사용하며 `response.completed` 수신을 성공 조건으로 삼습니다. 현재 네이티브 [ModelStreamPlugin](../android/app/src/main/java/dev/earlydreamer/jhfreader/ModelStreamPlugin.java)의 `/v1/chat/completions` 경계와 다른 전송입니다. [공식 모델과 추론](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)

현재 `ProviderSession.completeJson`은 비스트리밍·온도·출력 상한을 사용하는 반면, 이 경로는 지원하지 않는 필드가 있습니다. 기존 용어집 생성·다수결 판정 지원을 그대로 표시할 수 없습니다. [공식 프리뷰 제한](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

### 단계별 검증과 통과 조건

| 단계 | 구현·검증 범위 | 다음 단계로 넘어갈 조건 |
| --- | --- | --- |
| A 인증 왕복 | 별도 검증 앱 또는 개발용 경로에서 시스템 브라우저, loopback 리스너, PKCE·state·nonce 검증, 토큰 교환과 앱 복귀를 확인합니다. | 지정한 Android 버전·브라우저에서 긴 로그인·취소·앱 전환·잠금·프로세스 종료·오래된 콜백을 처리합니다. 성공·취소·시간 초과 뒤 리스너가 닫힙니다. |
| B 세션 보호 | 검증한 계정·등록 ID와 토큰을 묶어 보호 저장하고 갱신을 직렬화합니다. 로그아웃과 원격 철회 결과를 구분합니다. | 재시작·계정 변경·갱신 실패에서 계정이 섞이지 않고 일반 설정·백업·로그에 토큰이 없습니다. |
| C 최소 추론 | 고정 OpenAI 목적지 전송과 Responses SSE 파서를 추가하고, 계정 모델 목록에서 선택한 모델로 합성 짧은 문단을 한 번 수동 번역합니다. | `response.completed`까지 확인합니다. 한도·권한 오류·불완전 응답·중단을 성공으로 저장하지 않고 자동 재전송하거나 다른 과금 경로로 전환하지 않습니다. |
| D 도입 판단 | 인증 복귀 안정성·지연·표시 가능한 사용량·데이터 보존 결과를 정리합니다. | 도입·보류를 결정하고 제품 구현을 선택하면 독서·저장·제목·용어 기능의 지원 범위를 별도 이슈로 정합니다. |

A가 실패하면 B·C와 제품 설정 노출로 진행하지 않고 정확한 제약을 #307에 기록합니다. 인증 리스너는 화면 전환 시 스트림을 취소하는 기존 플러그인과 수명을 분리합니다. 검증되지 않은 새 계정으로 활성 계정을 바꾸지 않습니다. 인증 상태는 대기·교환·성공·취소·실패로 구분하며, 프로세스 종료 뒤 남은 인증 시도를 자동 재개하지 않습니다.

B에서는 Android Keystore 기반 보호 저장을 재사용할 수 있는지 확인하되 OAuth 갱신·철회 수명은 별도로 관리합니다. 원격 철회를 확인하지 못한 로그아웃을 완전한 철회로 표시하지 않습니다. 플랜 사용량은 앱 전용 할당량으로 설명하지 않으며 연결 화면에서 공유 한도와 원문 전송을 안내합니다. [공식 계정과 세션](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)

C까지 통과해도 자동 용어집·정밀스캔·제목 번역·미리 번역 지원이 완료된 것은 아닙니다. 현재 앱 설정·서재·저장본을 보존한 검증 환경에서 진행하고, 실제 로그인·사용량을 쓰는 단계는 #307의 별도 PoC 착수 범위를 정한 뒤 사용자 참여로 검증합니다. 이번 설계 작업에서는 인증 등록이나 모델 호출을 수행하지 않습니다.

## Gemini 재구현의 재개 조건

#29의 최신 댓글은 기존 구현을 숨기고 재구현이 필요하다고 설명합니다. [Gemini 구현 문서](gemini-provider.md)와 [전체 회차 제공자](../src/providers/gemini/wholeChapter.ts)도 현재 비스트리밍 단일 요청의 범위를 보여 줍니다. 기존 본문의 과거 병합 체크만으로 현재 앱의 기능 통합이 완료됐다고 판단하지 않습니다.

재개를 선택하면 다음 순서로 진행합니다.

1. 본문·제목 번역, 스트리밍, 문단 재번역, 자동 용어집, 정밀스캔을 각각 지원·미지원으로 명시합니다. 로컬 경로와 같은 기능을 보장하려면 그 범위를 먼저 합의합니다.
2. 당시 Google 공식 문서의 모델·API·요금·데이터 조건을 확인하고, 세션·전송·기능 지원 여부에 맞춰 UI를 제한합니다. 키 헤더와 고정 Google 목적지, 차단·결과 불명 시 미저장·자동 대체 금지 경계를 유지합니다.
3. 선택한 하나의 사용자 동작부터 전용 이슈·워크트리·PR로 구현합니다. 사용자 독서 기능과 별도 정밀스캔을 한 PR에 누적하지 않습니다. 공통 계약 변경이 실제로 필요하면 사용하는 기능과 함께 검증 가능한 선행 이슈로 분리합니다.
4. 모의 전송 회귀 후 지정한 계정·전송 데이터·비용 범위에서 실제 Android 호출, 저장·재열기, 오류와 기존 데이터 보존을 검증합니다. 그 결과에 맞춰 설정 UI에 노출합니다.

ChatGPT PoC의 성공이 Gemini 구현의 선행 조건은 아닙니다. 두 제공자에서 구체적으로 공유할 책임이 확인되기 전에 범용 제공자 프레임워크를 만들지 않습니다.
