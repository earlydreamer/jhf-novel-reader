# 별명 뜻 분해 비교 실험

이슈 [#219](https://github.com/earlydreamer/jhf-novel-reader/issues/219)는 기존 세 번 판정 앞에 별명의 뜻을 분해하는 요청을 한 번 추가했을 때 표기·분류가 개선되는지 비교합니다. 앱 기본 스캔에는 활성화하지 않으며, 진단 명령을 명시적으로 실행할 때만 추가 요청을 보냅니다.

## 비교 조건

합성 별명 12건과 작품명·지명·일반 이름 반례 8건을 `tools/diagnostics/nickname-cases.json`에 고정합니다. 원래 재현 이름 `美濃の蝮`과 그 대상을 가리키는 합성 조회 응답을 포함합니다. 실제 소설 문단이나 외부 위키 조회 결과를 수집하지 않습니다. 기대 표기·허용 대안과 사례 파일 hash를 실행 전에 고정합니다.

기준군은 앱의 현재 판정 요청·파서·온도 `0, 0.7, 0.7`·다수결을 사용합니다. 실험군은 `の`가 있고 작가 루비가 없는 후보마다 뜻 분해 요청을 최대 한 번 추가하고, 검증한 결과만 최종 요청의 `meaning:` 참고 줄에 넣습니다. 모델의 제안은 조회 근거로 표시하지 않습니다. 부적합한 뜻 분해 결과는 기존 판정으로 진행하며, 취소·결과 불명·인증 오류는 재전송 없이 비교를 중단합니다.

각 군을 세 차례 실행하고 실행 순서를 교대합니다. 양쪽 군의 같은 반복·묶음·투표에는 같은 seed를 사용합니다. 뜻 분해 요청과 판정 요청은 직렬로 보내며, 후보·사전·고정 조회·모델·서버 설정을 양쪽에서 동일하게 유지합니다. 공유 서버의 다른 작업에 따른 지연은 통제하지 않으므로 지연 결과는 해당 실행 조건의 측정값입니다.

## 실행

이미 실행 중인 로컬 모델만 사용합니다. 원격 서버는 별도로 구성한 SSH 로컬 포워드를 사용하고, 진단 명령은 `127.0.0.1` HTTP 주소만 허용합니다. 서버 포트를 공개하거나 모델을 자동으로 새로 불러오지 않습니다. 모델 이름은 현재 목록과 일치하는 ID 또는 파일 이름을 지정합니다.

```text
node tools/diagnostics/nickname-compare.mjs --base http://127.0.0.1:18082 --model gemma-4-E4B-it-UD-Q4_K_XL.gguf --out .local-work-records/nickname-comparison.json
```

필요하면 `--cases 1 --repetitions 1`로 짧은 연결 검사를 먼저 실행할 수 있습니다. 이 결과는 전체 비교나 채택 조건 충족으로 집계하지 않습니다. 출력 경로는 새 파일이어야 합니다. 진행률은 요청·실험군·반복과 시간만 출력하고, 각 군을 완료할 때 부분 결과를 저장합니다. 결과 JSON은 소스 커밋·파일 hash·사례 hash·모델 파일 이름과 문맥 크기·요청 수·시간, 합성 사례의 최종 표기·분류·정오 판정을 보관합니다. 원시 모델 응답·판정 이유·인증값·서버 주소는 저장하지 않습니다.

## 판정

표기 비교는 공백과 전각·반각을 정규화하며, 허용 표기·이름 종류·분류가 모두 맞아야 정답으로 셉니다. 정확한 기대 표기 목록에 없는 동의 표현은 자동으로 정답 처리하지 않으므로 이 점을 결과 해석에 반영합니다.

- 20건 전체에 대해 양쪽 군의 세 차례 결과가 모두 있어야 채택 여부를 판단합니다.
- 원래 재현 사례가 실험군에서 세 번 모두 맞고, 별명 정답 수가 증가하며, 반례 정답 수가 줄지 않고 잘못된 별명 분류가 늘지 않아야 품질 개선으로 판정합니다.
- 품질 조건을 통과해도 완료 시간 중앙값이 기준의 1.5배를 넘으면 기본 적용을 보류합니다.
- 부분 비교는 `incomplete`, 품질 조건 미달은 `reject`, 시간 초과는 `defer_latency`로 기록합니다. `candidate_for_product_review`도 자동 제품 적용을 뜻하지 않습니다.

이 비교는 판정까지만 수행하여 저장소에 쓰지 않습니다. 사람 항목 보존과 실제 앱 통합은 제품 적용을 선택한 뒤 별도로 검증합니다. 실제 결과와 채택·중단 판단은 #219와 관련 PR에 기록합니다.
