# 번역 제공자

앱은 로컬 서버(OpenAI 호환 서버)와 Gemini로 번역합니다. 제공자를 바꿔도 같은 기능을 같은 규칙으로 제공하는 것이 원칙입니다. 아래 표는 현재 코드의 기능별 지원 상태이고, 지원하지 않는 칸은 해소할 이슈와 연결합니다.

## 제공자별 기능 지원

| 기능                         | 로컬 서버 | Gemini |
| ---------------------------- | --------- | ------ |
| 회차 번역과 저장             | 지원      | 지원   |
| 작품 용어집 적용             | 지원      | 지원   |
| 말투 적용                    | 지원      | 지원   |
| 이야기 요약 적용             | 지원      | 지원   |
| 공용 용어집 적용             | 지원      | 지원   |
| 문단 재번역                  | 지원      | 지원   |
| 실패 문단 자동 재번역        | 지원      | 지원   |
| 읽는 회차 자동 번역          | 지원      | 지원   |
| 제목 직접 번역               | 지원      | 지원   |
| 제목 자동 번역               | 지원      | 지원   |
| 제목 번역의 용어집 적용      | 지원      | 지원   |
| 자동 용어집                  | 지원      | 지원   |
| 용어 정밀스캔                | 지원      | 지원   |
| 미리 번역 후보의 표기 채우기 | 지원      | 지원   |
| 구간 일괄 번역               | 지원      | 지원   |

[제공자 기능 검사](../tests/integration/provider-capabilities.test.tsx)는 실제 앱 조립에 합성 응답을 연결하고 모든 제공자에 같은 관찰을 적용합니다. "지원" 칸은 기능이 실제로 동작해야 하고, "미지원" 칸은 동작하지 않아야 통과합니다. 같은 검사가 이 표와 테스트의 지원 표가 일치하는지도 확인합니다. 기능을 지원하게 되면 표와 테스트를 함께 고칩니다.

표기 채우기·정밀스캔·일괄 번역의 세부 동작은 각 기능의 통합 검사가 다룹니다. 이 표의 검사는 제공자 때문에 기능이 막히거나 빠지는지를 봅니다. 미리 번역 후보의 표기 채우기는 후보가 있는 미리 번역 검토에서 판정 요청을 보내고 채우기를 마치는지 확인합니다.

### 지원하지 않는 칸의 이유

현재 두 제공자 모두 지원하지 않는 칸이 없습니다. 새 제공자에 지원하지 않는 칸이 생기면 막는 코드 위치와 해소 이슈를 여기에 적습니다.

### 요청 방식의 차이

아래 차이는 같은 기능을 제공자에 맞게 요청하는 방식입니다. 기능 지원 여부와 구분합니다.

- **번역 방식**: 로컬 서버는 읽으며 번역(스트리밍)·구간 번역·일반 텍스트 중에서 고릅니다. Gemini는 스트리밍을 쓸 수 있으면 스트리밍으로 정해지고 방식을 고르지 않습니다. 표의 로컬 서버 열은 기본 방식인 읽으며 번역을 기준으로 합니다.
- **참고 정보**: 로컬 서버의 일반 텍스트 방식은 참고 데이터를 보낼 수 없어, 용어집·말투가 적용되는 회차는 번역하지 않고 안내합니다. 구간 번역은 표기와 말투를 보내지만 이야기 요약은 보내지 않습니다. Gemini는 참고 정보가 없는 회차를 전체 회차 한 번으로 요청하고, 참고 정보가 있으면 로컬 스트리밍과 같은 문단 단위로 요청합니다.
- **제목 요청**: 로컬 서버는 스트리밍 연결이면 제목도 스트리밍 문단 번역으로 요청합니다. Gemini는 비스트리밍으로 요청하며, 적용할 표기가 있는 제목 묶음만 본문처럼 문단 단위로 보내고 표기가 없으면 제목 전체를 한 번에 보냅니다. 두 제공자 모두 본문과 같은 선별 규칙을 씁니다. 작품 용어집과 공용 용어집의 표기를 참고로 넣고, 작품 용어집 표기는 필수 표기로 확인합니다.
- **판정 요청**: 자동 용어집·정밀스캔은 두 제공자 모두 JSON 응답 형식과 temperature를 지정합니다. 정밀스캔은 temperature `0, 0.7, 0.7`로 세 번 판정합니다.
- **저장본 출처**: 저장본에는 `provenance.provider`로 제공자를 기록합니다. 독서 화면의 번역 정보는 Gemini 저장본을 `Google Gemini`, 나머지를 `OpenAI 호환`으로 표시합니다.

## 새 제공자를 추가할 때

1. 위 표에 제공자 열을 추가하고 칸마다 지원 여부를 정합니다. 지원하지 않는 칸에는 이유를 적고 해소 이슈를 연결합니다.
2. [제공자 기능 검사](../tests/integration/provider-capabilities.test.tsx)의 `PROVIDER_LABELS`·`SUPPORT`에 같은 내용을 넣고, 하네스에 연결 절차와 합성 응답 형식을 추가합니다. 기존 관찰은 바꾸지 않고 새 제공자도 같은 관찰을 통과하게 합니다.
3. temperature를 받지 않는 것처럼 제공자 고유의 제약은 "요청 방식의 차이"에 적습니다. 판정 횟수·저장 기준처럼 결과에 영향을 주는 규칙은 다른 제공자와 같게 유지합니다.
4. 저장본 출처 표시와 설정·저장 형식 검증(`readingValidation.ts`, `storage/legacy/validation.ts`)에 새 제공자를 추가합니다.

ChatGPT 열은 [#422](https://github.com/earlydreamer/jhf-novel-reader/issues/422)~[#424](https://github.com/earlydreamer/jhf-novel-reader/issues/424)에서 추가합니다.

## 로컬 OpenAI 호환 제공자

현재 앱은 `src/providers/plainText.ts`의 `createProviderSession`과 모델 목록 조회 기능을 사용합니다. `src/providers/localStreaming.ts`는 스트리밍 번역을 담당합니다. 이슈 #3의 `createOpenAICompatibleProvider`·문단 JSON 계약은 초기 구현 기록이며 현재 실행 진입점이 아닙니다.

### 연결과 인증

`normalizeOpenAICompatibleBaseUrl`로 HTTP/HTTPS 서버 루트 또는 `/v1` API 기본 주소를 정규화합니다. 역방향 프록시의 `/v1` 접두 경로도 지원합니다. 루트·끝 슬래시 차이를 정리하고 `/chat/completions`를 한 번만 붙입니다. 작업 전체 URL, 지원하지 않는 경로, 쿼리, fragment, URL 안의 인증 정보는 거부합니다.

모델은 사용자의 연결에서 조회한 목록을 바탕으로 선택합니다. 휴대전화에서 `localhost`는 휴대전화 자체를 가리킵니다. 기존 PC 서버의 접근 가능한 주소를 입력해야 합니다. 앱이 방화벽·서버 설정을 바꾸거나 서버를 인터넷에 공개하지는 않습니다.

`authRef`가 없으면 인증값을 조회하거나 Authorization 헤더를 만들지 않습니다. 참조가 있으면 요청 직전에 보안 저장소에서 읽고 Bearer 헤더에 넣습니다. 키 자체는 설정·URL·저장본 식별자·원문 요청·로그에 넣지 않습니다. 교체된 인증 참조의 보존·회수는 [인증값 보존](renewal/credential-retention.md)에 따릅니다.

HTTP에서는 인증 헤더와 원문도 암호화되지 않습니다. 신뢰할 수 있는 네트워크나 HTTPS 연결을 사용합니다. 로컬 서버를 골랐다는 사실만으로 서버가 선택한 모델까지 로컬에서 실행한다고 보장할 수 없으므로 서버의 모델 설정을 확인합니다.

### 현재 요청 방식

로컬 제공자는 선택한 번역 방식에 따라 일반 텍스트, 줄 ID 기반 묶음 번역, 스트리밍을 처리합니다. 묶음 번역은 입력·출력 예산에 맞게 나누고 필요한 경우 제한된 이어 보내기를 수행합니다. 스트리밍은 문단 ID와 순서를 검증하며 도착한 결과부터 표시합니다. 현재 회차 흐름을 “항상 POST 한 번”으로 설명하지 않습니다.

컨텍스트 추정치는 실제 모델 토크나이저·채팅 템플릿의 보장이 아닙니다. 서버가 실제로 불러온 컨텍스트 용량을 늘리는 기능도 아닙니다.

`stop`은 완료, `length`는 길이 제한, `content_filter`는 차단으로 해석하며 알 수 없는 종료 이유를 완료로 간주하지 않습니다. 원문에 포함된 지시·URL을 실행하거나, 모델 응답으로 외부 도구를 호출하지 않습니다. 일부 결과를 표시하더라도 저장 전 상태와 완성본을 구분합니다.

### 오류와 재시도

401/403은 인증 오류로 처리합니다. 다른 HTTP 오류는 허용한 상태·오류 코드로 분류하며 원시 응답·키·원문을 오류 메시지에 노출하지 않습니다. 알려진 입력·출력 한도 오류와 통신 결과 불명을 구분합니다.

요청을 보내기 전 취소하면 전송하지 않습니다. 이미 보낸 요청은 취소해도 서버 처리 여부를 단정할 수 없습니다. 결과 불명 상태를 자동 재전송하거나 다른 제공자로 우회하지 않습니다. 스트리밍의 실패 문단 검증 후 제한적인 재시도는 별도 설정과 계약에 따르며, 통신 결과 불명·인증 오류의 자동 재시도와는 다릅니다.

### 초기 문단 JSON 계약 기록

초기 제공자는 비스트리밍 요청 한 번에 `stream:false`, `model`, `max_tokens`와 두 메시지를 보냈습니다. 출력은 `{ "paragraphs": [{ "id": "...", "text": "..." }] }`였으며, 정확한 ID 순서·비어 있지 않은 번역·완료 종료 이유를 요구했습니다. JSON 보정이나 코드 펜스 추측은 하지 않았습니다. 직렬화한 메시지의 UTF-8 바이트 수에 256의 포맷 여유와 출력 예약량을 더하는 보수적인 추정치를 사용했습니다.

당시 합성 테스트는 Ollama·LM Studio 응답 형식, 선택적 인증, 주소 정규화, 예산 초과, 잘못된 JSON·ID, 종료 이유, HTTP 오류, 취소를 검증했습니다. 실제 서버·기기·원문 사이트·유료 API를 호출한 증거는 아니었습니다.
