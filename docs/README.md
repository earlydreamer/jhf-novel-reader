# 문서 안내

목적에 맞는 문서부터 읽습니다. 현재 사용법과 개발 안내는 아래 목록을 기준으로 확인합니다.

## 처음 사용하는 경우

[프로젝트 소개와 설치 방법](../README.md)에서 준비물, 번역 서버 연결, 앱의 주요 기능을 확인합니다.

## 코드를 수정하는 경우

1. [기여 안내](../CONTRIBUTING.md)에서 작업 브랜치와 PR 흐름을 확인합니다.
2. [개발 환경과 검사](development-checks.md)에 따라 실행하고 검사합니다.
3. [아키텍처](architecture.md)에서 현재 코드의 역할과 앱 흐름을 확인합니다.

동작별 설명은 [원문 가져오기](source.md), [번역 제공자](providers.md), [독서 흐름](integration.md), [저장소](storage.md)에 정리합니다. [Gemini 제공자 구현](gemini-provider.md)는 현재 지원 범위를 먼저 확인한 뒤 읽습니다.

다음 작업의 범위는 [후속 작업 우선순위와 단계별 설계](follow-up-design.md)에서 확인합니다. 구현 제안과 기존 후순위·보류 결정을 구분하여 읽습니다.

[외부 서비스 연동 연구와 제품 도입 결정](external-service-research.md)은 ChatGPT 연구 브랜치 보존, main 미병합 결정, 제공자 정책·개인정보처리방침·법률 검토의 선행 조건을 정리합니다.

[별명 뜻 분해 비교 실험](nickname-experiment.md)은 합성 사례로 기존 판정과 추가 뜻 분해를 비교하는 명시적 실행 절차입니다.

## 화면과 문구를 수정하는 경우

- [디자인 시스템](../DESIGN.md)에서 색, 글꼴, 컴포넌트와 화면 규칙을 확인합니다.
- [디자인 시스템 미리보기](design-system.html)에서 컴포넌트와 상태를 직접 확인합니다.
- [UX 라이팅 가이드](ux-writing.md)에서 문구의 목적과 표현 원칙을 확인합니다.
- [화면 검증 안내](ui.md)에서 합성 미리보기와 기기 검증의 차이를 확인합니다.

## 검증하거나 배포하는 경우

[Android 검증 안내](android-validation.md)는 APK 빌드, 출처 확인, 네이티브 검사와 실제 기기 검증을 구분합니다. [릴리스 안내](release.md)는 유지관리자가 서명과 배포를 준비할 때 사용합니다. 상세 작업·병합·정리 규칙은 [유지관리 문서](maintaining.md)에 있습니다.

## 문서를 작성하는 경우

프로젝트가 작성하는 설명은 한국어 합니다체로 씁니다. 독자가 해야 할 일과 확인할 근거를 앞에 두고, 긴 문단과 중복 설명을 줄입니다. 명령, 코드 식별자, 경로, API 이름은 그대로 유지합니다.

GitHub 이슈·PR·댓글은 [GitHub 글 작성 기준](github-writing.md)에 따라 한국어 합니다체와 용도별 구조를 사용합니다. 기존 글의 정보와 당시 상태를 보존하는 소급 수정 절차도 이 문서에 있습니다.

제3자 라이선스 전문과 권리자가 요구한 고지는 번역으로 대체하지 않습니다. 개인 실행 로그와 작업 기록은 저장소 밖에서 보관합니다. 법률 원문과 생성형 고지의 범위는 [제3자 고지](../THIRD_PARTY_NOTICES.md)를 참고합니다.
