# 저장본 재개 위치의 누적 이동 수정

2026-10-26에 저장본 재개 위치가 누적 이동하는 결함을 재현하고 수정했습니다. [#385](https://github.com/earlydreamer/jhf-novel-reader/issues/385) / [PR #386](https://github.com/earlydreamer/jhf-novel-reader/pull/386)의 범위이며, [카쿠요무 검증에서 관찰한 20px 차이](2026-10-26-kakuyomu-android.md)를 후속 조사했습니다. 이전 검증 당시 결과는 그대로 보존합니다.

## 재현과 원인

Black Shark 2(Android 10, WebView 155.0.8059.43)의 기존 저장본을 6,000px에서 읽고 앱을 force-stop한 뒤 서재의 '이어서 읽기'로 재개했습니다. 재번역 없이 같은 저장본으로 세 번 반복하자 안정화된 scrollTop이 5,980 → 5,960 → 5,940px로 이동했습니다. 글꼴은 모든 표본에서 로딩 완료 상태였으며, 본문 위 padding도 51px로 일정했습니다.

저장 위치를 복원할 때는 원문 제목만 보이고, 저장된 번역 제목이 비동기로 도착하면 원문 제목을 함께 표시하면서 머리글이 20px 늘어났습니다. 원문 확인 안내도 약 32.4px 높이와 아래 여백 16px로 나타났다 사라졌습니다. 같은 본문 문단의 offsetTop은 5,978 → 6,046 → 5,998px로 바뀌었습니다.

기존 코드는 최초 위치만 복원하고 기본 CSS의 smooth scroll을 적용했습니다. 제목·안내가 바뀌는 동안 이동 중간 좌표를 새 위치로 저장했고, 배치 변경 뒤에 원래 문단 안 위치를 다시 맞추지 않았습니다. smooth scroll만 끈 진단 실험에서도 6,000 → 6,020px 차이가 남아, 즉시 복원과 레이아웃 변경 후 문단 기준 유지가 함께 필요했습니다.

## 변경

저장 위치 복원과 원문 보기에서 번역 보기로 돌아오는 이동은 잠시 `scroll-behavior: auto`로 즉시 수행한 뒤 기존 inline 스타일을 돌려놓습니다. 일반 독서 스크롤의 CSS 설정은 유지합니다.

제목·안내·독서 설정이 바뀌면 현재 문단과 문단 안 offset으로 위치를 맞춥니다. 사용자가 이미 스크롤했다면 최신 위치를 사용하고 처음 저장 위치로 되돌리지 않습니다. 다른 버전으로 이동하거나 원문을 보는 동안, 미리보기 번역이 진행되는 동안에는 이 복원을 적용하지 않습니다. 저장 형식과 모델 요청은 변경하지 않았습니다.

웹 빌드·Capacitor sync·`assembleDebug`·APK 감사를 통과한 뒤 기존 앱을 `install -r`로 업데이트했습니다. 설치 직후, 앱을 열기 전 기존 파일 35개(서재 30개)의 SHA-256이 모두 같았습니다. 이 기록을 추가한 후속 문서 커밋은 실제 설치 소스와 구분합니다.

## 실제 기기 결과

| 검증 | 결과 |
| --- | --- |
| 최초 위치 | 6,000px |
| 종료·재개 1회 | 6,000px, 같은 문단의 offset 2 |
| 종료·재개 2회 | 6,000px, 같은 문단의 offset 2 |
| 종료·재개 3회 | 6,000px, 같은 문단의 offset 2 |
| 원문 보기 → 번역 보기 | 번역 위치 6,000px 유지, 양쪽 343문단/블록 |
| 사용자 스크롤 후 종료·재개 | 8,200px로 옮긴 새 위치가 재개 후에도 8,200px |

제목·안내가 로딩되는 동안 절대 scrollTop은 배치에 맞게 바뀌지만 같은 본문 문단 안 offset이 유지됩니다. 레이아웃이 안정화된 뒤의 좌표와 반복 재개를 비교했으며, 모든 로딩 프레임의 절대 scrollTop이 같다고 판정하지 않습니다.

원래 저장본의 versionId·chapterId·생성 시각·번역문 SHA-256·343개 블록이 유지됐습니다. 전체 검증 후에도 기존 4작품·완성 번역 2개가 남았습니다. 기존 35파일 중 30파일은 같은 해시였고, 바뀐 5개는 시험 회차 읽기 위치 2개·공용 서재 인덱스 2개·Android 실행 프로필입니다. 파일 추가·누락은 없었으며 기존 나로우의 저장본·읽기 위치와 연결·독서 설정은 유지됐습니다.

## 자동 검사와 한계

수정 전 새 회귀 테스트 2개가 실패했고, 수정 후 리더 테스트 64개와 전체 124개 파일·1,774개 테스트가 통과했습니다. 늦은 제목·안내 반영, 사용자 스크롤 이후 위치 보존, 즉시 복원을 검사했고 기존 원문 보기·다른 버전 회귀도 통과했습니다. Node v24.22.1에서 format·lint·typecheck·웹 빌드·diff 검사와 APK 감사를 통과했습니다. 기존 500kB 초과 청크 경고는 남아 있습니다.

실기 검증은 위 Black Shark 2의 기존 카쿠요무 저장본에서 수행했습니다. KEY2·iOS, 회전·화면 크기 변경, 아직 로딩 중인 글꼴의 교체는 실기로 확인하지 않았습니다. 이번 시험은 저장본 재개이며 새 번역을 만들지 않았습니다. 실제 소설 본문·번역문·사설 주소·인증정보는 공개 기록에 포함하지 않습니다.
