# pixiv Android 탐색·번역·저장·재개 검증

2026-10-28에 Black Shark 2의 기존 앱을 데이터를 유지하는 업데이트로 설치하고, pixiv 공개 작품으로 다음 흐름을 확인했습니다.

- 원문 브라우저 탐색
- '이 작품 열기'로 작품 추가
- 실제 모델 번역·저장, 프로세스 종료 후 재개
- 용어 후보 스캔의 요청 간격
- 지원하지 않는 작품 거부

측정 중 결함 두 개를 찾아 같은 브랜치에서 고쳤습니다. 결함 하나는 이번 범위에서 고치지 않았습니다. Refs #390.

요청 간격은 페이지에서 Capacitor 네이티브 HTTP 호출 시각을 기록해 측정했습니다. 기록한 값은 URL 경로, 시각, 상태뿐이고 본문은 기록하지 않았습니다.

## 측정 중 찾은 결함

1. **`i.pximg.net` 표지 403.** 이 호스트는 Referer가 없는 이미지 요청에 403을 주고, `https://www.pixiv.net/`이 있으면 200을 줍니다. pixiv 프로필의 헤더 허용 목록이 비어 있어서 loader가 Referer를 뺐습니다. 이 출처 값 하나만 허용하도록 고쳤습니다(`a98b1ee`).
2. **손으로 탭한 SPA 이동에서 버튼이 꺼진 채로 남음.** pixiv 시리즈 링크를 탭하면 pushState가 진행률 100 미만에서 일어나는 경우가 있었습니다. 진단 로그로 3회 중 1회를 확인했고, 그때 진행률은 10이었습니다. 그러면 `doUpdateVisitedHistory`가 갱신을 건너뛰고, 같은 문서 안의 이동이라 `onPageFinished`도 오지 않습니다. 그래서 '이 작품 열기'와 '뒤로 가기'가 비활성으로 남았습니다. 진행률 대신 `onPageStarted`~`onPageFinished` 사이인지로 갱신을 미루도록 고쳤습니다(`521d485`).
   - 진단 로그를 넣은 빌드에서 링크가 실제로 이동한 4회 모두 두 버튼이 켜졌습니다. 그중 1회는 진행률 0이었습니다.
   - 카쿠요무 작품 링크는 전체 페이지 로드였고, 로드 중의 갱신은 건너뛴 뒤 `onPageFinished`에서 켜졌습니다. #377의 동작은 유지됩니다.
   - 진단 로그는 커밋하지 않았습니다.
3. **태그 목록 화면 오류(고치지 않음).** 원문 브라우저는 `setDomStorageEnabled(false)`로 `localStorage`를 끕니다(`SourceBrowserActivity`, 계측 테스트가 단언). pixiv 태그 목록 페이지는 시작할 때 `localStorage.getItem`을 부르다가 `null` 오류로 멈춥니다. 원문 브라우저의 저장소 격리 경계에 관한 결정이라 이번 변경에 넣지 않았습니다. 소설 홈·랭킹·시리즈·회차 페이지와 '이 작품 열기'는 영향을 받지 않습니다.

## 기존 데이터 보존

설치 전에 기존 APK와 앱 전용 `files`·`shared_prefs`를 비공개 로컬 경로에 백업했습니다. 업데이트 직후, 앱을 시작하기 전에는 기존 파일 35개가 모두 같은 SHA-256이었습니다. 그중 서재 파일은 30개입니다.

전체 검증 후에도 기존 파일 중 사라진 것은 없습니다. 기존 서재 파일 30개 중 20개가 그대로입니다. 기존 번역 2개, 읽기 위치, 작품 제목, 용어집이 여기에 포함됩니다. 바뀐 10개는 다음과 같습니다.

- 새 pixiv 작품·번역을 기록한 공용 서재 인덱스 2개
- 번역 시도 인덱스 2개
- 일괄 작업 상태 2개
- 기존 4작품의 목차 파일 4개

목차 파일 4개는 앱의 정기 새 회차 확인이 다시 저장한 것입니다. 세 작품은 쓰기 세대와 체크섬만 바뀌었고, 한 작품은 실제 새 회차 2개가 목록 끝에 붙었습니다. 서재 인덱스에는 기존 번역 2개·작품 4개·최근 기록 2개가 모두 남았습니다.

저장된 설정 값 중 바뀐 것은 연결 확인 때 증가하는 `selection.connection.revision`(58 → 60)뿐입니다. Android 프로필·WebView 내부 설정 파일의 변경은 서재 데이터 보존과 구분합니다.

## 자동 검사와 한계

`b1be7ab`에서 다음 검사를 실행했습니다.

- format·lint·typecheck·build는 통과했습니다.
- 전체 테스트는 첫 실행에서 `tests/diagnostics/hymt2-fidelity.test.ts`의 한 테스트가 20초 시간 초과로 실패했습니다. 이 브랜치는 그 영역을 바꾸지 않았습니다. 같은 파일을 단독으로 실행하면 통과했고, 전체를 다시 실행하자 127개 파일·1,809개 테스트가 모두 통과했습니다.

JVM `:app:testDebugUnitTest`는 Windows에서 78개 중 72개가 통과했고 6개가 실패했습니다. 이 환경에서는 원문 브라우저 계열(`SourceSitesTest`·`SourceBrowserPolicyTest` 포함)이 모두 통과했습니다. 실패 6개는 이 브랜치가 바꾸지 않은 백업 계열 테스트입니다.

- 5개는 [Android 검증 안내](../android-validation.md)에 기록된 비-POSIX 환경 실패입니다.
- `stagedReadsRejectTraversalAndCanonicalEscapeAndEnforceByteLimit`는 Windows에서 심볼릭 링크를 만들 권한이 없어 실패했습니다.

POSIX 환경의 전체 결과는 Linux CI로 확인합니다.

다음은 확인하지 않았습니다.

- 기기 계측 테스트(`connectedDebugAndroidTest`)
- 로그인 전용 작품과 R-18 작품의 실제 거부. 단위 테스트로만 확인했습니다.
- 검색 화면을 따로 측정하지 않았습니다. 태그 목록과 같은 경로로 추정되지만 확인하지 않았습니다.
- 비행기 모드 재개
- 백업 복원
- KEY2 등 다른 기기
- 번역의 의미·말투 품질

실제 소설 본문·원시 모델 입출력·인증정보·사설 주소·작품 식별자는 공개 기록에 포함하지 않습니다.
