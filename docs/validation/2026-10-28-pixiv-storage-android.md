# pixiv 원문 브라우저 메모리 저장소 Android 검증

2026-10-28에 Black Shark 2의 기존 앱을 데이터를 유지하는 업데이트로 설치했습니다. pixiv 태그 목록이 원문 브라우저에서 열리는지와 메모리 `localStorage`의 범위를 확인했습니다. Refs #393.

## 검증한 설치본

| --- | --- |
| 제품 소스 | `560e514463844db701a88e39868b0e98093b437d` |
| 소스 tree | `c36476d0bc3838e3bca033c423f136d3aa7fb290` |
| APK SHA-256 | `3d3093e7c5eac5ce6918f82bf86328883191c0e0f77ca08c7da8d976e91fae8e` |
| APK 출처 | 웹·네이티브 출처가 위 커밋·tree와 일치하며 `dirty: false` |
| 기기 | Black Shark 2, Android 10, WebView 155.0.8059.43 |

설치 전 기기의 앱은 #391 검증 때 설치한 `521d485` 빌드였습니다. 이 문서를 추가한 후속 커밋은 설치 소스가 아닙니다.

## 실제 앱에서 확인한 흐름

| 단계 | 관찰 결과 |
| --- | --- |
| pixiv 소설 홈 | `localStorage`가 `null`이 아니라 메모리 저장소 객체였습니다. |
| 태그 목록 | 홈의 태그 링크를 손으로 탭했습니다. "Application error" 없이 목록이 열렸고, 작품 링크 90개·시리즈 링크 19개가 있었습니다. 이미지는 하나도 깨지지 않았습니다. |
| 태그 목록 2페이지 | 2페이지 링크를 탭하자 pixiv 회원가입 화면(`signup.php`)으로 이동했습니다. 서버는 같은 주소의 HTML에 200을 줬으므로, 페이지 스크립트가 보낸 이동입니다. 로그인하지 않은 사용자에 대한 pixiv 쪽 제한으로 추정하지만 확인하지 않았습니다. |
| 필터 탭 | 'オリジナル作品' 탭을 눌렀지만 주소와 목록 수가 바뀌지 않아, 적용 여부를 판단하지 못했습니다. |
| 태그 목록 → 시리즈 → 작품 추가 | 목록의 시리즈를 탭하자 '이 작품 열기'와 '뒤로 가기'가 켜졌습니다. '이 작품 열기'로 57화 시리즈가 서재에 추가됐습니다. |
| 값이 남지 않음 | pixiv 페이지에서 `localStorage.setItem`으로 값을 넣었습니다. 페이지를 다시 불러오자 값은 `null`, 길이는 0이었습니다. WebView 프로필의 `Local Storage` 기록에는 pixiv 출처와 시험 키가 없었습니다. |
| 다른 사이트 | 나로우·카쿠요무 페이지의 `localStorage`는 그대로 `null`이었습니다. 나로우 홈이 열렸고, 카쿠요무 작품 링크를 탭하면 두 버튼이 켜졌습니다. |

## 기존 데이터 보존

설치 전 앱 전용 `files`·`shared_prefs` 파일 49개 중 사라진 것은 없습니다. 바뀐 서재 파일은 새 작품을 기록한 공용 서재 인덱스 2개뿐입니다. 서재 인덱스에는 기존 번역 3개·작품 5개·최근 기록 3개가 모두 남았습니다. 설정 값 중 바뀐 것은 연결 확인 때 증가하는 `selection.connection.revision`(60 → 61)뿐입니다.
