# 화면과 문구 문서 안내

현재 화면을 확인할 때는 다음 문서를 사용합니다.

- [디자인 시스템](../DESIGN.md): 색, 글꼴, 크기, 컴포넌트와 화면 배치 규칙을 설명합니다.
- [인터랙티브 디자인 시스템](design-system.html): 컴포넌트와 상태를 직접 눌러 확인하는 HTML 문서입니다. 파일을 내려받아 브라우저에서 엽니다.
- [UX 라이팅 가이드](ux-writing.md): 현재 앱의 문구와 상태 안내 원칙을 설명합니다.


## 앱 화면 미리보기

`npm run dev`를 실행한 뒤 개발 서버의 `/tests/ui/renewal-preview.html`을 엽니다. 390 × 844 크기의 합성 데이터 미리보기이며 실제 번역 요청은 보내지 않습니다. 제품 진입점에서도 이 파일을 불러오지 않습니다.

화면 테스트는 jsdom과 Testing Library를 사용합니다. 브라우저에서 확인한 화면과 Android 기기의 인셋, 뒤로 가기, 글꼴 설정 검증은 구분합니다. 기기 검증 절차는 [Android 검증 안내](android-validation.md)를 따릅니다.

## 새 회차 검사

서재와 작품 목차의 상단 앱 바에 있는 **새로고침 아이콘**으로 각각 전체·개별 검사를 요청합니다. 작품 메뉴의 **새 회차 확인**도 사용할 수 있습니다. 확인 모달 본문은 전체 검사에 ‘서재에 있는 모든 작품의 목차를 최신화해요.’, 개별 검사에 ‘이 작품의 목차를 최신화해요.’ 한 문장만 표시합니다. 모든 수동 검사는 확인 모달을 거치며 **확인하기**를 눌러야 실행합니다. 취소·뒤로 가기는 요청하지 않습니다. 검사 중에는 해당 아이콘이 비활성화되고 결과는 스낵바로 알려 줍니다. 수동 검사는 날짜 제한 없이 실행하며 같은 작품의 진행 중인 요청은 합칩니다. 서재에는 새 회차 수, 작품 목차에는 숫자 없는 **새 회차** 배지를 표시합니다. 배지는 원문 최초 등록 후 48시간 이내이면서 실제 읽기 위치 기록이 없는 회차에만 붙습니다. 목차·번역 화면 진입이나 번역 저장만으로 읽음 처리하지 않습니다. 읽기 위치가 저장되면 48시간 이내여도 배지를 숨기며, 재검사·재실행에서도 읽기 기록을 반영합니다. 등록 후 정확히 48시간까지 표시하고 이후에는 서버 요청 없이 배지만 만료시킵니다. 개정 시각은 기준이 아닙니다. 성공적으로 목차를 갱신하면 새 회차 유무와 관계없이 **회차 목록을 갱신했어요.** 토스트를 띄웁니다. 전체 검사는 완료 토스트를 한 번만 표시합니다.

**설정 → 새 회차 검사 → 자동 검사 주기 (일)**의 기본값은 1일이며 1~365일을 지정할 수 있습니다. 각 작품의 마지막 검사 날짜를 기기의 로컬 날짜로 저장하고, 그 날짜에서 N일 뒤 0시부터 자동 검사 대상이 됩니다. 예를 들어 10월 20일 23시에 1일 주기로 검사하면 다음 대상 시점은 10월 21일 0시입니다. 앱이 활성 상태면 예약 시점에 검사하고, 앱을 닫아 두거나 백그라운드라면 다음 실행·복귀 때 밀린 검사를 한 번 수행합니다. 화면 왕복만으로 요청하지 않습니다.

실패한 검사도 검사 날짜에 포함합니다. 기존 목차·마지막 성공 시각을 보존하고 배지는 등록 시각·읽기 기록에 따라 표시하며 짧은 간격의 자동 재시도는 하지 않습니다. 수동 검사는 즉시 다시 할 수 있습니다. 검사가 자정을 넘겨 끝나면 끝난 날짜를 사용해 완료 직후 중복 검사를 막습니다. 

여러 목차 페이지를 끝까지 조회해 목록과 최초 등록 시각을 저장합니다. 처음 등록한 작품과 기존 작품 모두 같은 48시간·읽기 기록 기준을 사용합니다. 날짜가 없거나 잘못된 기존 목차는 임의로 신규로 간주하지 않으며, 다음 갱신에서 등록 시각을 가져옵니다. 오래된 회차도 목록에는 반영합니다. 새 회차 검사는 목차를 갱신하며 번역 본문을 자동으로 가져오거나 번역을 시작하지 않습니다.
