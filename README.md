# narou-reader

일본 웹소설의 URL을 넣으면 본문을 가져와 한국어로 번역하고, 휴대폰에서 이어 읽을 수 있도록 만드는 리더입니다.

소설가가 되자(小説家になろう, Syosetu)를 첫 대상으로 합니다. 사용자가 이미 쓰고 있는 로컬 LLM에 연결하는 것을 우선하고, 필요하면 직접 설정한 클라우드 API도 사용할 수 있게 할 계획입니다.

> 한 회차의 본문 추출·로컬 모델 번역·검증·저장·읽기 흐름을 연결했습니다. 합성 HTML과 응답 모형으로 검증하며, 실제 사이트 접근·기기·로컬 모델 연결과 사용 가능한 APK 검증은 별도입니다. 다음 한 화 미리 번역은 아직 활성화하지 않았습니다.

## 왜 만드는가

원문을 복사해 번역 도구에 넣고, 번역문을 읽다가 다음 화로 이동하는 과정을 줄이고 싶습니다. URL 입력부터 번역, 읽기까지 한 화면 흐름으로 연결하는 것이 목표입니다.

이를 위해 모바일 앱이 본문 수집과 번역 요청을 직접 처리합니다. PC에는 기존 Ollama 또는 LM Studio만 실행해 두고, 이 프로젝트를 위한 별도 동반 프로그램이나 백엔드, 프록시 서버는 설치하지 않는 구조를 선택했습니다.

## 기본 사용 흐름

1. 설정에서 번역 제공자, 엔드포인트, 모델을 지정합니다. 인증이 필요한 제공자는 인증 정보도 입력합니다.
2. 읽을 소설의 URL을 넣습니다.
3. 앱이 해당 페이지의 HTML을 가져와 제목과 본문, 이동에 필요한 링크를 추출합니다.
4. 선택한 LLM으로 일본어 본문을 한국어로 번역합니다.
5. 현재 화의 번역이 끝나면 읽기 화면에 표시하고, 완료된 번역과 읽던 위치를 기기에 저장합니다.
6. 이전 화나 다음 화로 이동합니다. 필요하면 원문도 확인합니다.

로컬 LLM을 사용할 때는 휴대폰에서 PC의 API 주소에 접근할 수 있어야 합니다. 로컬 연결에 실패했다고 본문을 클라우드로 자동 전송하지 않으며, 클라우드 API는 사용자가 선택한 경우에만 사용하도록 설계합니다.

## MVP 범위

첫 배포 대상은 웹 UI를 감싼 Android APK입니다. iOS는 이후 단계로 둡니다.

- URL 입력과 지원 주소 확인
- Syosetu 본문 추출
- OpenAI 호환 API를 통한 로컬 LLM 연결
- 현재 화 번역 완료 후 표시
- 원문 확인, 이전·다음 화 이동, 글자 크기 조절
- 완료된 번역과 읽던 위치 저장 및 복원
- 연결 실패, 본문 추출 실패, 번역 실패를 구분한 안내와 재시도
- 선택 기능으로 다음 한 화 미리 번역

### 다음 화 미리 번역

미리 번역은 기본값을 **꺼짐**으로 둡니다. 사용자가 켜면 현재 화를 읽는 동안 다음 한 화만 준비합니다.

앱이 전면에 있을 때만 작업하며, 중단된 작업은 저장한 체크포인트를 기준으로 다시 열었을 때 이어갈 수 있도록 설계합니다. 앱 종료나 운영체제의 백그라운드 제한 이후에도 번역이 계속되는 동작은 보장하지 않습니다. 전체 작품을 한꺼번에 가져오거나 연속으로 미리 번역하는 기능은 포함하지 않습니다.

## 구조와 책임

```text
소설 URL
  → 모바일 앱의 네이티브 HTTP 요청
  → 소스별 파서로 본문 추출
  → 번역 제공자 어댑터
      ├─ 사용자 PC의 Ollama / LM Studio
      └─ 사용자가 선택한 클라우드 API
  → 완료된 번역 저장
  → 읽기 화면과 읽던 위치 복원
```

- **모바일 앱**: URL 처리, HTML 요청과 파싱, 번역 요청, 읽기 화면, 로컬 저장을 담당합니다.
- **로컬 LLM**: 기존 API 서버로 번역 요청을 받습니다. 소설 수집이나 앱 전용 서버 역할은 맡기지 않습니다.
- **번역 제공자 어댑터**: 제공자별 요청·응답 차이를 분리합니다. OpenAI 호환 API를 먼저 구현하고 Gemini 등 클라우드 API 지원은 이후 확장으로 둡니다.
- **앱 전용 저장소**: 완료된 번역, 읽던 위치, 작업 체크포인트를 저장하도록 설계합니다.

운영자가 소설 본문을 수집하거나 번역을 중계하는 서버는 두지 않습니다. 클라우드 제공자를 선택하면 번역할 본문이 해당 제공자에게 전송되며, 사용량에 따른 비용과 데이터 처리 정책을 확인해야 합니다.

API 키를 앱에 공용으로 내장하지 않습니다. 사용자 인증 정보는 운영체제의 보안 저장소를 사용하는 방향으로 설계하며, 구체적인 저장 방식과 로그 노출 방지는 구현 단계에서 검증합니다.

## 기술 구성

기반 의존성과 실행 설정을 추가했습니다. 고정 버전, 모듈 계약과 보안 경계는 [구조 문서](docs/architecture.md)에 정리했습니다.

- **React + TypeScript + Vite**: 모바일 읽기 화면과 설정 UI
- **Capacitor**: Android 패키징과 네이티브 기능 연결
- **네이티브 HTTP 계층**: 모바일 앱에서 원문 HTML과 LLM API 요청 처리
- **소스별 파서**: LNReader의 Syosetu 파싱 로직을 필요한 범위로 분리·적용
- **번역 제공자 어댑터**: OpenAI 호환 API 우선, 이후 Gemini 등 확장
- **로컬 영속 저장과 보안 저장소**: 읽기 데이터와 인증 정보를 용도에 맞게 분리

네이티브 HTTP의 실제 동작, 로컬 API 연결, 저장 방식은 Android 기기에서 먼저 검증합니다.

## 이번 범위에서 제외하는 것

- 대규모 서재, 작품 검색·추천, 전체 작품 일괄 수집
- EPUB 생성과 내보내기
- 회원가입, 계정, 기기 간 동기화
- 운영자 백엔드와 번역 중계 서버
- PC 전용 동반 프로그램
- 앱이 닫힌 상태에서의 지속적인 번역
- 번역문 공개 공유와 재배포

## 개발 순서와 작업 방식

먼저 한 화를 끝까지 읽는 흐름을 검증하고, 그다음 복원과 미리 번역을 붙입니다.

1. Android 앱 껍데기와 URL·설정·읽기 화면 구성
2. 허용된 HTML 샘플로 본문 추출과 화면 표시 검증
3. 로컬 LLM 연결과 한 화 번역 흐름 구현
4. 완료된 번역·읽기 위치 저장, 실패 처리와 체크포인트 복원
5. 선택형 다음 한 화 미리 번역
6. 클라우드 제공자 확장과 iOS 검토

구현은 GitHub Flow를 기준으로 진행합니다. 이슈 단위로 범위와 완료 조건을 정하고 브랜치를 나눕니다. 병렬 작업은 별도 worktree를 사용하고, 같은 파일을 동시에 수정하지 않도록 책임을 구분합니다. 변경 사항은 관련 테스트와 검증 결과를 포함한 Draft PR로 올린 뒤 검토합니다.

파서는 HTML 샘플 기반 테스트로, 번역 계층은 응답 모형과 실패 사례로 검증합니다. 기기 검증에서는 네트워크 단절, 재시도, 화면 이동, 앱 중단과 재실행 시의 복원도 확인할 계획입니다.

## 소스 재사용과 이용 범위

본문 추출에는 [LNReader의 Syosetu 플러그인](https://github.com/LNReader/lnreader-plugins/blob/master/plugins/japanese/Syosetu.ts)을 재사용할 계획입니다. 해당 저장소는 [MIT License](https://github.com/LNReader/lnreader-plugins/blob/master/LICENSE)를 적용하며, 코드를 가져올 때 필요한 저작권·라이선스 고지를 함께 유지합니다. narou-reader 자체의 라이선스는 아직 정하지 않았습니다.

파서의 라이선스와 소설 본문을 가져오고 번역할 수 있는 권한은 별개입니다. 기기에서 직접 요청한다는 이유만으로 자동 수집이나 재배포가 허용되는 것은 아닙니다. 원문 사이트의 이용 조건과 저작권을 확인해야 하며, 나로우의 자동 접근 제한에 맞는 이용 범위는 아직 해결해야 할 항목입니다. 실제 사이트 연동과 공개 배포에 앞서 이 부분을 별도로 확인합니다.


## 개발 실행

Node.js 22.12 이상을 사용합니다. CI 기준은 Node 24입니다.

```sh
npm ci
npm run typecheck
npm test -- --run
npm run build
npm run dev
```

Android 프로젝트에 웹 빌드와 플러그인을 반영하려면 `npm run android:sync`를 실행합니다. APK 빌드에는 Java 21과 Android SDK 36이 필요하며 실기기 검증은 별도입니다. 브라우저에서는 화면과 합성 테스트를 확인할 수 있습니다. 실제 요청·저장은 네이티브 환경에서만 동작하며, 네이티브 HTTP와 보안 저장소를 웹의 평문 대체 구현으로 연결하지 않습니다. 한 회차 통합의 취소·재시도·오프라인 복원 경계는 [통합 문서](docs/integration.md)에 정리했습니다.

테스트는 합성 데이터와 mock만 사용합니다. 실제 사이트 접근, 유료 API 호출, 배포 권한을 뜻하지 않습니다.
